# ステップ2 音響改善案（優先度順）

> 当時の提案。採否と現行の仕様は [decisions.md](decisions.md) を参照（食い違うときはそちらが優先）。

前提: concept.md / decisions.md（D1〜D8）。量子化なし・sim が唯一の発音判定（D4）・決定論性は変えない。

## 案1（最優先）: ハーモニーの移ろい（8小節ごとにスケールが変わる）
- **狙い**: 線を増やさなくても、放置しているだけで景色が変わるようにする（「放置しても展開し続ける」）。現状は C ペンタが固定なので、5分聴くと単調になる
- **仕様**:
  - 線に固定するのは「スロット」（今の `note` = 0..15）のまま。実際の音高は **衝突した step** で決める
  - スケールは C 基準の音高クラス5つ（昇順）で持つ: `C=[0,2,4,7,9]` `F=[0,2,5,7,9]` `G=[2,4,7,9,11]`
  - 進行 `PROG=[C, F, C, G]`（I–IV–I–V）。どのスロットも移動は ±2 半音以内に収まり、隣り合うスケールは4音を共有するので滑らかに移る
  - `midi = 48 + 12·octave + PROG[sec][degree]`
  - `sectionSteps = round(SECTION_BARS × 4 × 7200 / BPM)`、`SECTION_BARS = 8`（BPM 90 → 2560 step ≈ 21.3s、1周 ≈ 85s）
  - `sec = (harmonyBase + floor((step − harmonyAnchor) / sectionSteps)) mod 4`
  - `setTempo` のときは、その step の sec を `harmonyBase` に、step を `harmonyAnchor` に入れ直す（テンポを変えても進行は途切れない）
  - GUI に `harmony: on/off` を追加する（off なら sec=0 に固定）
- **変更**: `sim/music.ts`（SCALES・PROG・`midiAt(slot, sec)` の純関数）、`sim/constants.ts`（SECTION_BARS）、`sim/sim.ts`（`bounce` で midi と sec を計算、`applyCommands` で anchor を管理、`setHarmony` コマンド）、`sim/types.ts`（HitEvent に `midi`・`section` を追加、Command）、`audio/audio.ts`（`play` は `e.midi` から周波数を出す。16音のテーブルはやめる）、`main.ts`（GUI）
- **決定論性・D4**: 音高は sim のイベントの中で step とコマンド履歴だけから決まる → 同じ配置・同じ操作なら同じ曲になる。音と光は同じイベントから作るので 1:1 は崩れない
- **裁定の改訂**: D6「音程は線を作った時点で固定」を「**スロットと色は固定、音高は区間で ±2 半音まで動く**」に改める。D7 に `midi` と `section` を追加する
- **描画との連携**: 必須ではない（線の色はスロットで決めているので変わらない）。区間が切り替わるとき、背景や残像にごく弱い色の変化を入れるなら `section` を渡せる。visual 担当に相談する

## 案2: 音域ごとの音色（低音は柔らかく長く、高音はきらめいて短く）
- **狙い**: 5分間聴いたときの耳の疲れを減らす（C6 付近で modIndex 3.5 × 3倍音は刺さる）。重なったときに音域ごとの役割が分かれ、にじまずに聞こえる
- **仕様**（`t = slot / 15`、0 が最低音）:
  - `harmonicity`: t<0.34 → 2（丸い）、t<0.67 → 3、それ以上 → 4（ガラス的）
  - `modulationIndex = (1.2 + 2.8·t) × (0.6 + 0.4·velocity)`（強く当たるほど明るい）
  - `envelope.decay = 2.4 − 1.5·t` 秒、音価 = decay × 0.85
  - 音量補正 `+2 − 4·t` dB（ラウドネス曲線の補償。低音が埋もれないようにする）
- **実装方針**: PolySynth は声部ごとにパラメータを変えられないので、**自前のボイスプール**（FMSynth × 24、ラウンドロビン、足りないときは一番古い声部を止めて使う）に置き換える。発音時に `setValueAtTime(…, time)` で設定する。止める声部はイベント列だけで決まるので、発音結果も決定論的
- **変更**: `audio/audio.ts`（`start` でプール生成、`play` でパラメータ設定）。sim は変えない
- **決定論性・D4**: 影響なし（イベントの中身は変わらない）。現状の「PolySynth 上限で音を捨てる」は「古い声部を止める」に変わるので、**取りこぼしで光だけになることがなくなり**、1:1 はむしろ強くなる
- **描画との連携**: 不要。任意で、低音は発光の減衰を長く、高音は短くすると音の尾と揃う（visual 担当に相談）

## 案3: 線の x 座標によるステレオ定位
- **狙い**: プロジェクターの左右のスピーカーで、画面の位置と音の位置を一致させる。音が重なっても分離して聞こえる
- **仕様**:
  - `pan = stereoWidth × (2·e.x / 1920 − 1)`、`stereoWidth` の初期値は 0.7（GUI で 0〜1。モノラル PA の会場では 0 にする）
  - 衝突点の x を使う（長い線の端と端で定位が変わり、動きが感じられる）
  - 案2のボイスプールの各声部に `Tone.Panner` を付け、`pan.setValueAtTime(pan, time)` で設定する
  - FeedbackDelay を `PingPongDelay`（delayTime・feedback 0.28・wet 0.18 は同じ）に置き換えて、左右の広がりを出す
- **変更**: `audio/audio.ts`、`main.ts`（GUI）。sim は変えない（`HitEvent.x` はすでにある）
- **決定論性・D4**: 影響なし
- **描画との連携**: 不要

## 実装順と確認
- 案2 → 案3 は同じボイスプールの上に作るので、続けて実装する。案1は sim と型の変更を含むので、physics・visual 担当に D6/D7 の改訂を先に共有する
- 合格基準: 線5本で10分放置し、進行が少なくとも7周（案1）してもうるさく感じないこと。CPU 使用率が MVP と比べて大きく増えないこと（ボイス数は 24 のまま）

# 設計の統合と裁定（ステップ1）

audio.md / visual.md / physics-architecture.md の食い違いを、以下のとおり裁定する。
ここに書いたものが各設計案より優先される。

## D1. 物理の周波数: 120Hz
- physics 案を採用。`stepsPerBeat = 7200 / BPM`。BPM 90 → 80 ステップ/拍で割り切れる
- audio 案の 240Hz は不採用（音のタイミング精度は D3 で担保する）

## D2. 座標系: 論理 1920×1080・y 下向き・px
- visual 案を採用。物理は常に 1920×1080 の論理座標で動く → ウィンドウサイズが変わっても結果は同じ
- 表示は画面比を保って縮小し、余白は黒（レターボックス）
- 音程マッピングの「画面幅比」は論理幅 1920 に対する比

## D3. 時間の同期: オーディオ時計を主にし、描画は lookahead ぶん遅らせる
- 物理の時計は AudioContext の時刻から導出する: `targetStep = floor((ctx.currentTime - t0 + LOOKAHEAD) * 120)`
  - 物理は常に LOOKAHEAD（0.05s）だけ先行して進む
- 衝突の発音時刻は `t0 + step / 120`（ステップ単位で正確なので、リズムが揺れない）
- 描画は「現在時刻」の世界を表示する: `renderStep = (ctx.currentTime - t0) * 120 + visualOffset`
  - ボール位置は直近 16 ステップぶんのリングバッファから補間
  - 発光は `renderStep - event.step` から計算 → 当たった瞬間に光り、同時に鳴る
- audio 案の「即時発音（Tone.immediate）」と physics 案の「アンカー + lookahead」は、この形に統合する
- `visualOffsetMs` は GUI で会場ごとに調整できるようにする（出力レイテンシの補正）

## D4. 発音と発光は常に 1:1
- 衝突を「鳴らす・光らせる」判定は **物理（sim）側だけ** で行う。sim が出したイベントは必ず鳴って必ず光る
  - 速度しきい値: 法線速度 80 px/s 未満はイベントを出さない
  - 同じボールが同じ線に 8 ステップ以内に再び当たった場合はイベントを出さない
  - 同じ線は 7 ステップ（約 60ms）のクールダウン中はイベントを出さない
- visual 案の「鳴らなかった衝突を弱く光らせる」は不採用（concept の音と光の完全一致を優先）
- PolySynth の上限による音の取りこぼしは許容する（5分間放置のテストで問題になったら見直す）

## D5. 線の最小長: 58px（論理幅の 3%）
- audio 案のマッピング範囲（比 0.03〜0.6）に合わせる。58px 未満は確定させない（プレビューはグレー）

## D6. 音程・色・定数の共有
- `sim/` に共有定数を置く: `BALL_RADIUS=5`, `LINE_WIDTH=3`, `MIN_LINE_LEN=58`, `G`, `HZ=120`
- `lengthToDegree(len)` は `music.ts` の純関数にして、audio と render（色）の両方から使う
- 音程と色は線を作った時点で固定する（回転しても変わらない）

## D7. 衝突イベントの型（最終）
```ts
type HitEvent = {
  kind: 'hit'
  step: number        // 物理ステップ番号（時刻の唯一の基準）
  ballId: number
  lineId: number
  x: number; y: number
  normalSpeed: number // 反射前の法線方向の速度 (px/s)
  velocity: number    // 0..1、音量と発光強度に共通で使う
  degree: number      // スケール内のインデックス（線に固定）
}
```

## D8. レビューを受けての追加裁定

チームのレビュー（audio / visual / physics）を受けて追加・修正する。

1. **遅延からの復帰**（audio・physics が致命的と指摘）
   - 1フレームで進める物理は最大 8 ステップ
   - 遅れが 0.1s を超えたら `t0` をずらして基準を取り直し、飛ばした時間は捨てる（タブ復帰や GC 停止の対策）
   - 発音時刻が `currentTime - 0.02s` より過去のイベントは、**音も光も捨てる**（D4 の 1:1 を守る）
2. **時計は1本**: `t0` と発音時刻はすべて `rawContext.currentTime` を基準にする。Tone の `lookAhead = 0`、`Tone.now()` は使わない。`t0` は `Tone.start()` と `reverb.ready` を待った後に決める
3. **描画用の時刻**: `ctx.getOutputTimestamp()` と `performance.now()` を対応づけて滑らかにする（currentTime の段差でのカクつき対策。出力遅延の補正も兼ねる）
4. **履歴バッファは 64 ステップ**（約 0.53s）。`visualOffsetMs` は GUI で [−150, +40] にクランプする
5. **描画は renderStep に揃える**: ボールの出現と消滅（スナップショットに存在するかで判定）、線の追加と削除、発光、ボールの色変化は、すべて `renderStep ≥ event.step` になってから反映する
6. **放出**: 放出間隔は `periodSteps = round(beats × 7200 / BPM)` を一度だけ計算して整数で固定する。`emit` イベントを追加する（放出口のパルス用）
7. **入力**: マウス座標はレターボックスを引いてスケールで割り、論理座標にしてから扱う。最小長と当たり判定も論理 px で判定する
8. **回転速度の上限**: 線ごとに `ω_max = 0.9 × R × 120 / halfLen`（R は当たり判定半径）で制限する。長い線ほど遅く回る
9. **線のクールダウン**: 7 ステップ以内の同時衝突は1つにまとめる。複数の放出口のボールが同じ線に同時に当たった場合も1音になるが、これは意図した仕様とする（決定論的なので同じ配置なら毎回同じ）
10. **定数**: `V_REF = sqrt(2·G·1080)`、`V_MIN = 80`、`REST_VN = 40`（これ未満は跳ねずに滑る）、`vel = 0.12 + 0.88·x^0.6`、`x = clamp((vn − V_MIN)/(V_REF − V_MIN))`。すべて `sim/` に置く

# ステップ3の裁定: MIDI 出力

## D10. MIDI
- **ライブ出力**: Web MIDI で外部へ送る（Mac は IAC Driver → GarageBand / DAW）。Chrome など Web MIDI 対応ブラウザのみ
  - note on は内蔵音と同じ時刻に予約送信する: `performance.now() + (audioTime − currentTime)·1000 + offsetMs`
  - note off は予約せず、毎フレームの `midi.update()` で期限が来たものを送る。同じ音がその後に鳴り直していれば送らない（連打した新しい音を切らないため）
  - 同じ音が鳴っている最中の再発音は、直前に note off を送ってから note on
  - 音高は `HitEvent.midi`（ハーモニー込み）、velocity は `round(velocity·127)`、チャンネルは GUI で 1〜16
  - 内蔵音は GUI でオフにできる（DAW の音色だけで鳴らすとき）
- **録音**: 衝突を step 基準で記録し、Standard MIDI File（フォーマット0）で書き出す。Web MIDI 非対応のブラウザでも使える
  - 開始は次の拍の頭に揃える（DAW に読み込んだときに小節線が合うように）
  - テンポは録音開始時の BPM。録音中に BPM を変えても、秒単位の時刻は正しい（小節線だけがずれる）
- **OSC**: 「連携はシンプルに」の方針で見送り（ブラウザからは UDP を送れず、中継サーバーが必要になるため）

## D8-3 の修正
- Tone が自動で作る AudioContext は互換ラッパーで、`getOutputTimestamp` を持っていなかった。このため D8-3（描画用時刻の平滑化）はステップ1から効いておらず、`currentTime` にフォールバックしていた
- ネイティブの AudioContext を自前で作って Tone に渡すよう変更した（`Audio.setupContext`）。MIDI の時刻合わせにも使う

## D10 レビューを受けての修正
- SMF: 同じチャンネル・同じ音が重なったら、次の note on の時刻で前の音を打ち切る
- ライブ: note off の管理を (チャンネル, 音高) 単位にし、チャンネル変更・タブ非表示・ページ離脱で全ノートオフ
- note on の予約時刻は `getOutputTimestamp` で対応を取り、内蔵音が **聞こえる** 時刻に揃える（出力遅延込み）。note off は先送りせず期限が来てから送る
- 放出時刻を `anchor + round(k·beats·7200/BPM)` に変更（整数周期の足し合わせでは、7200 を割り切らない BPM で誤差がたまり、録音がグリッドからずれるため）
- 録音中にテンポや周期を変えたら、そこまでを保存して録音を止める
- 遅れて捨てた衝突（LATE_DROP）も録音には入れる（録音は step 基準なので位置は正しい）

# ステップ4の裁定: 楽しさ（演出）

ユーザーが選んだもの: おすすめ4つ（置く前に音が聞ける／弦が鳴る／連鎖の光／バンパー）、曲らしさ（共鳴／盛り上がり／鳴り続ける柔らかい音）、ミュートボタン、**線以外も引ける（手描き・図形を置く）**。
見送り: 線をつかんで動かす＋Undo、世界を傾ける、分裂ボール、弧、線の種類ごとの楽器、スマホから参加。

## D11. D4 の例外（ユーザーが「曲らしさ」を選んだため認める）
- 置いた瞬間の確定音と、引いている途中のティック: 入力へのフィードバック。**MIDI には送らない・録音しない**
- 共鳴（同じスロットの線がほのかに光る）: 光だけ。衝突の光より明らかに弱くする
- パッド（持続音）: 音だけ。光は放出口がゆっくり呼吸する程度。**MIDI には送らない**
- それ以外（衝突の音と光）は今までどおり 1:1、判定はすべて sim で行う

## D12. 図形（shape）: 手描き・円・三角・四角をひとまとまりとして扱う
- 1本の線も「辺が1つの図形」とみなす。**図形 = 同じ `group` を持つ Segment の集まり**
- **音程は図形ごとに1つ**。周の長さ（全辺の長さの合計）を `lengthToNote` に通す（元の案「大きさで音程」）。1本の線は今までどおり
- 回転: 図形全体がその重心のまわりに回る（1本の線は今までどおり中点のまわり）
- 右クリックの消去・ホバーは図形単位
- 衝突の判定は図形単位: 同じボールと同じ図形のクールダウン（BALL_LINE_COOLDOWN）と、図形のクールダウン（LINE_COOLDOWN）は **group をキーにする**。角で隣り合う2辺に同時に当たっても1回だけ鳴る
- 入力（ツール）: 1 = 線、2 = ペン（手描き）、3 = 円、4 = 三角、5 = 四角。GUI でも選べる
  - ペン: 点列を Ramer–Douglas–Peucker で単純化（許容 4px 程度）、辺は最大 48 本
  - 円・三角・四角: ドラッグの始点が中心、終点までの距離が半径、終点の向きが回転角。円は正24角形
  - Shift を押しながら描くとバンパー
- 保存形式 v2（v1 も読める）: `shapes: [kind, dir, closed, ...flatPoints][]`。座標は整数、回転中でも描いたときの座標で保存
- MAX_SEGS（全辺の合計）は 400 のまま。超える図形は追加しない

## D13. バンパー
- `Segment.kind: 'line' | 'bumper'`（図形単位で同じ値）
- 反発係数 1.2、反射後の速さの上限あり（画面外へ飛び去り続けないように）。音と光は普通の線と同じ規則（アタックが強い音色にしてもよい）

## D14. 契約の変更（`src/sim/types.ts`）
- `Segment` に `group: number`（図形 id）と `kind: SegKind` を追加
- `Command` に `{ kind: 'addShape'; points: [number, number][]; closed: boolean; segKind: SegKind; dir?: 1|-1 }` を追加（`addSegment` は2点の addShape として残す）。`removeSegment` は図形まるごと消す（`removeShape { group }` を追加し、removeSegment は id → group に読み替え）
- `HitEvent` に追加:
  - `group`, `segKind`
  - `chain`: そのボールが直前の衝突から 120 ステップ以内に **別の図形** に当たったら +1、そうでなければ 1
  - `energy`: 直近 2 小節（sectionSteps の 1/4）の衝突数 / 24 を 0..1 にクランプした値（決定論）
- `segmentAdded` を図形単位にする: `{ kind: 'shapeAdded'; step; group; segKind; note; midi; segments: Segment[] }`（`midi` は追加したステップの区間の音高 → 確定音に使う）。`segmentRemoved` は `{ kind: 'shapeRemoved'; step; group }`
- 新しいイベント: `{ kind: 'section'; step; section }`（区間の切り替わり。開始時にも1回出す）→ パッド用
- 回転は `segmentPose` を `shapePose { group, ... }` にして、描画は図形の重心と各頂点の相対座標から姿勢を作る

## D15. 各担当の範囲
- 物理: D12〜D14 の sim・scene・テスト
- 音: 確定音 `confirm(midi, time)`、ティック `tick(midi)`、パッド `setSection(section, time)`、energy による明るさ・ディレイ量・オクターブ上の重ね、バンパーの音色、ミュート `setMuted(on)`
- 映像: 弦が鳴る、連鎖の光（chain ≥ 3 で尾を強く、≥ 5 で通った図形を順に光らせ直す）、共鳴、energy でブルームを少し強く、放出口の呼吸、図形の描画、ツール入力（ペン・図形・Shift バンパー）、ドラッグ中のプレビュー音程の変化をコールバックで通知
- 統合（main）: ミュート（M キー＋GUI ボタン）、ツール選択の GUI とキー、配線、README

## ステップ4 統合時の補足
- ミュートは内蔵音と MIDI 出力の両方を止める（録音は続く）
- ティック音の音高は、ドラッグ中のスロットを今の区間で `midiAt` したもの
- 同じ時刻に確定音が重なる場合（配置の読み込みなど）は1回だけ鳴らす（Tone は同時刻の再発音で例外を投げるため）
- 閉じた図形が画面からはみ出す場合は、点ごとにクランプせず全体を平行移動して収める（形が潰れないように）
- 三角と四角は、右へ水平にドラッグしたとき頂点が上／辺が水平になる向きにする
- 当たった瞬間の大きな丸い滲みはブルームの低解像度段によるもので、ステップ3以前からある（今回むしろ小さくなった）。調整は投影で見てから

# ステップ5の裁定: 図形ごとの楽器

ユーザーの選択: **図形の形で楽器が決まる**（楽器を選ぶキーは足さない）、**キック（円）は拍にそろえる**。
参考にしたアンビエントの定石: キックは「押し出す」より「鼓動」— 高域を落とした丸いアタック、リバーブは薄く。打楽器はリズムより質感として小さく散らす。低・中・高で音域を分けて濁らせない。

## D16. 形と音色
| 形 | 音色 | 音高 |
|---|---|---|
| line | 今の FM ベル（旋律） | midiAt(スロット, 区間) |
| pen | はじく音（カリンバ／撥弦） | midiAt |
| circle | 柔らかいキック〜タム（MembraneSynth 系、ローパス、リバーブ薄め） | **kickMidi**: 区間の根音。大きい円ほど低いオクターブ（C1 / C2 / C3 帯） |
| triangle | 金属（トライアングル／チャイム／シンギングボウル）、余韻長め | midiAt（高めのオクターブに寄せてよい） |
| square | 木・クリック（ウッドブロック／リム）、短い | midiAt |
- バンパーは今までどおり、どの形でもアタックを強めて重ねる
- 形は `ShapeForm`（`src/sim/types.ts`）。sim の図形・HitEvent・shapeAdded が持つ。推定は `src/sim/form.ts` の `inferForm`
- 確定音（D11）も形の音色で鳴らす。ティック（描いている途中）は今のまま
- 光も形で性格を変える（1:1 は保つ）: circle = 図形全体が脈打つ＋輪が広がる、triangle = 細かくきらめいて長く残る、square = 短く鋭い閃光、line / pen = 今の弦の震え

## D17. キックを拍にそろえる（決定論、sim で行う）→ **D22 で取りやめ**
- circle に当たったら、衝突は物理的には今までどおり（跳ね返りはその場）。**鳴らすのは接触ステップ以降の最初の拍の頭**（ちょうど拍の頭ならそのステップ）
- 拍の格子: `harmonyAnchor + round(k · HZ · 60 / bpm)`（テンポ変更・読み込みで取り直す基準と同じ）
- sim は保留キックを持ち、その拍のステップで HitEvent を出す: `step` = 拍のステップ、`contactStep` = 接触ステップ、x, y は接触位置。chain・energy は接触時に計算
- **同じ circle は1拍に1回まで**。同じ拍に複数当たったら1つにまとめ、velocity は最大
- 図形が消えたら（removeShape / clear / loadScene）その図形の保留キックも捨てる
- main・audio・MIDI・録音・描画は `step` だけを見ればよい（今までと同じ流れ）

## D18. 保存形式
- `SceneData` に任意の `forms?: ShapeForm[]`（shapes と同じ順）を足す。v は 2 のまま
- forms が無い・長さが合わない・不正な値の要素は `inferForm` で推定（古い保存データも読める）

## D19. MIDI
- 円（キック）と四角（木）は GM ドラムとしてドラム用チャンネル（既定 10）へ: circle → 36（大）/ 45（中）/ 48（小）、square → 76（Hi Wood Block）/ 77（Low）
- line / pen / triangle は今までどおりのチャンネルに音高で送る
- 録音も同じ振り分け
- 保留にしていた「MIDI のチャンネル分け」はこれで最小限だけ入る（旋律側の分割は引き続き保留）

## D21. D17 の見直し: 当たったら鳴らし、拍の頭は「こだま」にする → **D22 で取りやめ**
ユーザーの感想: 拍まで待つと「当たって鳴る」感じがなく、ただ置いてあるだけに見える。エコーやディレイの結果として拍にそろうなら納得できる。
- circle も当たった瞬間に鳴らす（音・光ともに。ボールも光る）。D17 の保留とまとめ（1拍1回）はやめる
- そのあと、接触より後の拍の頭で **こだま** を ECHO_COUNT（2）回返す。velocity は ECHO_DECAY（0.5）の累乗で弱く、音量もさらに 1 回ごとに −4dB
- 同じ円にまた当たったら、残りのこだまは捨ててその音から数え直す。図形が消えたらこだまも捨てる。テンポを変えたら残りを新しい拍の格子に取り直す
- `HitEvent.echo`: 0 = 当たった音、1.. = こだま。こだまの区間と音高は鳴らすステップで決め直す。chain・energy には数えない
- こだまは内蔵音と光だけ（図形の脈と輪、弱く）。**MIDI・録音には当たった音だけを送る**（DAW 側のディレイに任せる）

## D22. 円も当たったら1回だけ鳴らす
ユーザーの判断: こだまも要らない。シンプルに1回鳴らす。エコーなどは、あとで「図形や線にエフェクトを掛けて、当たったあとどうなるかを設定できる」機能として足す。
- circle は他の形と同じく、当たったステップで1回だけ鳴らし光らせる（音高は kickMidi のまま）
- D17 の保留・拍そろえ、D21 のこだまは削除。`HitEvent.contactStep` / `echo` も削除
- 実装の参考は git 履歴に残る（拍そろえ: e9478a0、こだま: 91e02c1）

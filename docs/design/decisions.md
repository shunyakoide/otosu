# 設計の統合と裁定（ステップ1）

audio.md / visual.md / physics-architecture.md の食い違いを、以下のとおり裁定する。
ここに書いたものが各設計案より優先される。
（ここで名前の出てくる初期の設計案 concept.md / audio.md / visual.md / physics-architecture.md / step2-*.md は、実装とずれてきたので消した。git の履歴に残っている）

## D1. 物理の周波数: 120Hz
- physics 案を採用。`stepsPerBeat = 7200 / BPM`。BPM 90 → 80 ステップ/拍で割り切れる
- audio 案の 240Hz は不採用（音のタイミング精度は D3 で担保する）

## D2. 座標系: 論理 1920×1080・y 下向き・px
- visual 案を採用。物理は常に 1920×1080 の論理座標で動く → ウィンドウサイズが変わっても結果は同じ
- 表示は画面比を保って縮小し、余白は黒（レターボックス）→ **D23 で、余白にも図形を置けるように変更**
- 音程マッピングの「画面幅比」は論理幅 1920 に対する比

## D3. 時間の同期: オーディオ時計を主にし、描画は lookahead ぶん遅らせる
- 物理の時計は AudioContext の時刻から導出する: `targetStep = floor((ctx.currentTime - t0 + LOOKAHEAD) * 120)`
  - 物理は常に LOOKAHEAD（0.05s）だけ先行して進む
- 衝突の発音時刻は `t0 + step / 120`（ステップ単位で正確なので、リズムが揺れない）
- 描画は「現在時刻」の世界を表示する: `renderStep = (ctx.currentTime - t0) * 120 + visualOffset`
  - ボール位置は直近 16 ステップぶんのリングバッファから補間
  - 発光は `renderStep - event.step` から計算 → 当たった瞬間に光り、同時に鳴る
- audio 案の「即時発音（Tone.immediate）」と physics 案の「アンカー + lookahead」は、この形に統合する
- `visualOffsetMs` は GUI で会場ごとに調整できるようにする（出力レイテンシの補正）

## D4. 発音と発光は常に 1:1
- 衝突を「鳴らす・光らせる」判定は **物理（sim）側だけ** で行う。sim が出したイベントは必ず鳴って必ず光る
  - 速度しきい値: 法線速度 80 px/s 未満はイベントを出さない
  - 同じボールが同じ線に 8 ステップ以内に再び当たった場合はイベントを出さない
  - 同じ線は 7 ステップ（約 60ms）のクールダウン中はイベントを出さない
- visual 案の「鳴らなかった衝突を弱く光らせる」は不採用（concept の音と光の完全一致を優先）
- PolySynth の上限による音の取りこぼしは許容する（5分間放置のテストで問題になったら見直す）

## D5. 線の最小長: 58px（論理幅の 3%）
- audio 案のマッピング範囲（比 0.03〜0.6）に合わせる。58px 未満は確定させない（プレビューはグレー）

## D6. 音程・色・定数の共有
- `sim/` に共有定数を置く: `BALL_RADIUS=5`, `LINE_WIDTH=3`, `MIN_LINE_LEN=58`, `G`, `HZ=120`
- `lengthToDegree(len)` は `music.ts` の純関数にして、audio と render（色）の両方から使う
- 音程と色は線を作った時点で固定する（回転しても変わらない）

## D7. 衝突イベントの型（最終）
```ts
type HitEvent = {
  kind: 'hit'
  step: number        // 物理ステップ番号（時刻の唯一の基準）
  ballId: number
  lineId: number
  x: number; y: number
  normalSpeed: number // 反射前の法線方向の速度 (px/s)
  velocity: number    // 0..1、音量と発光強度に共通で使う
  degree: number      // スケール内のインデックス（線に固定）
}
```

## D8. レビューを受けての追加裁定

チームのレビュー（audio / visual / physics）を受けて追加・修正する。

1. **遅延からの復帰**（audio・physics が致命的と指摘）
   - 1フレームで進める物理は最大 8 ステップ
   - 遅れが 0.1s を超えたら `t0` をずらして基準を取り直し、飛ばした時間は捨てる（タブ復帰や GC 停止の対策）
   - 発音時刻が `currentTime - 0.02s` より過去のイベントは、**音も光も捨てる**（D4 の 1:1 を守る）
2. **時計は1本**: `t0` と発音時刻はすべて `rawContext.currentTime` を基準にする。Tone の `lookAhead = 0`、`Tone.now()` は使わない。`t0` は `Tone.start()` と `reverb.ready` を待った後に決める
3. **描画用の時刻**: `ctx.getOutputTimestamp()` と `performance.now()` を対応づけて滑らかにする（currentTime の段差でのカクつき対策。出力遅延の補正も兼ねる）
4. **履歴バッファは 64 ステップ**（約 0.53s）。`visualOffsetMs` は GUI で [−150, +40] にクランプする
5. **描画は renderStep に揃える**: ボールの出現と消滅（スナップショットに存在するかで判定）、線の追加と削除、発光、ボールの色変化は、すべて `renderStep ≥ event.step` になってから反映する
6. **放出**: 放出間隔は `periodSteps = round(beats × 7200 / BPM)` を一度だけ計算して整数で固定する。`emit` イベントを追加する（放出口のパルス用）
7. **入力**: マウス座標はレターボックスを引いてスケールで割り、論理座標にしてから扱う。最小長と当たり判定も論理 px で判定する
8. **回転速度の上限**: 線ごとに `ω_max = 0.9 × R × 120 / halfLen`（R は当たり判定半径）で制限する。長い線ほど遅く回る
9. **線のクールダウン**: 7 ステップ以内の同時衝突は1つにまとめる。複数の放出口のボールが同じ線に同時に当たった場合も1音になるが、これは意図した仕様とする（決定論的なので同じ配置なら毎回同じ）
10. **定数**: `V_REF = sqrt(2·G·1080)`、`V_MIN = 80`、`REST_VN = 40`（これ未満は跳ねずに滑る）、`vel = 0.12 + 0.88·x^0.6`、`x = clamp((vn − V_MIN)/(V_REF − V_MIN))`。すべて `sim/` に置く

# ステップ3の裁定: MIDI 出力

## D10. MIDI
- **ライブ出力**: Web MIDI で外部へ送る（Mac は IAC Driver → GarageBand / DAW）。Chrome など Web MIDI 対応ブラウザのみ
  - note on は内蔵音と同じ時刻に予約送信する: `performance.now() + (audioTime − currentTime)·1000 + offsetMs`
  - note off は予約せず、毎フレームの `midi.update()` で期限が来たものを送る。同じ音がその後に鳴り直していれば送らない（連打した新しい音を切らないため）
  - 同じ音が鳴っている最中の再発音は、直前に note off を送ってから note on
  - 音高は `HitEvent.midi`（ハーモニー込み）、velocity は `round(velocity·127)`、チャンネルは GUI で 1〜16
  - 内蔵音は GUI でオフにできる（DAW の音色だけで鳴らすとき）
- **録音**: 衝突を step 基準で記録し、Standard MIDI File（フォーマット0）で書き出す。Web MIDI 非対応のブラウザでも使える
  - 開始は次の拍の頭に揃える（DAW に読み込んだときに小節線が合うように）
  - テンポは録音開始時の BPM。録音中に BPM を変えても、秒単位の時刻は正しい（小節線だけがずれる）
- **OSC**: 「連携はシンプルに」の方針で見送り（ブラウザからは UDP を送れず、中継サーバーが必要になるため）

## D8-3 の修正
- Tone が自動で作る AudioContext は互換ラッパーで、`getOutputTimestamp` を持っていなかった。このため D8-3（描画用時刻の平滑化）はステップ1から効いておらず、`currentTime` にフォールバックしていた
- ネイティブの AudioContext を自前で作って Tone に渡すよう変更した（`Audio.setupContext`）。MIDI の時刻合わせにも使う

## D10 レビューを受けての修正
- SMF: 同じチャンネル・同じ音が重なったら、次の note on の時刻で前の音を打ち切る
- ライブ: note off の管理を (チャンネル, 音高) 単位にし、チャンネル変更・タブ非表示・ページ離脱で全ノートオフ
- note on の予約時刻は `getOutputTimestamp` で対応を取り、内蔵音が **聞こえる** 時刻に揃える（出力遅延込み）。note off は先送りせず期限が来てから送る
- 放出時刻を `anchor + round(k·beats·7200/BPM)` に変更（整数周期の足し合わせでは、7200 を割り切らない BPM で誤差がたまり、録音がグリッドからずれるため）
- 録音中にテンポや周期を変えたら、そこまでを保存して録音を止める
- 遅れて捨てた衝突（LATE_DROP）も録音には入れる（録音は step 基準なので位置は正しい）

# ステップ4の裁定: 楽しさ（演出）

作者が選んだもの: おすすめ4つ（置く前に音が聞ける／弦が鳴る／連鎖の光／バンパー）、曲らしさ（共鳴／盛り上がり／鳴り続ける柔らかい音）、ミュートボタン、**線以外も引ける（手描き・図形を置く）**。
見送り: 線をつかんで動かす＋Undo、世界を傾ける、分裂ボール、弧、線の種類ごとの楽器、スマホから参加。

## D11. D4 の例外（作者が「曲らしさ」を選んだため認める）
- 置いた瞬間の確定音と、引いている途中のティック: 入力へのフィードバック。**MIDI には送らない・録音しない**
- 共鳴（同じスロットの線がほのかに光る）: 光だけ。衝突の光より明らかに弱くする
- パッド（持続音）: 音だけ。光は放出口がゆっくり呼吸する程度。**MIDI には送らない**
- それ以外（衝突の音と光）は今までどおり 1:1、判定はすべて sim で行う

## D12. 図形（shape）: 手描き・円・三角・四角をひとまとまりとして扱う
- 1本の線も「辺が1つの図形」とみなす。**図形 = 同じ `group` を持つ Segment の集まり**
- **音程は図形ごとに1つ**。周の長さ（全辺の長さの合計）を `lengthToNote` に通す（元の案「大きさで音程」）。1本の線は今までどおり
- 回転: 図形全体がその重心のまわりに回る（1本の線は今までどおり中点のまわり）
- 右クリックの消去・ホバーは図形単位
- 衝突の判定は図形単位: 同じボールと同じ図形のクールダウン（BALL_LINE_COOLDOWN）と、図形のクールダウン（LINE_COOLDOWN）は **group をキーにする**。角で隣り合う2辺に同時に当たっても1回だけ鳴る
- 入力（ツール）: 1 = 線、2 = ペン（手描き）、3 = 円、4 = 三角、5 = 四角。GUI でも選べる
  - ペン: 点列を Ramer–Douglas–Peucker で単純化（許容 4px 程度）、辺は最大 48 本
  - 円・三角・四角: ドラッグの始点が中心、終点までの距離が半径、終点の向きが回転角。円は正24角形
  - Shift を押しながら描くとバンパー
- 保存形式 v2（v1 も読める）: `shapes: [kind, dir, closed, ...flatPoints][]`。座標は整数、回転中でも描いたときの座標で保存
- MAX_SEGS（全辺の合計）は 400 のまま。超える図形は追加しない

## D13. バンパー
- `Segment.kind: 'line' | 'bumper'`（図形単位で同じ値）
- 反発係数 1.2、反射後の速さの上限あり（画面外へ飛び去り続けないように）。音と光は普通の線と同じ規則（アタックが強い音色にしてもよい）

## D14. 契約の変更（`src/sim/types.ts`）
- `Segment` に `group: number`（図形 id）と `kind: SegKind` を追加
- `Command` に `{ kind: 'addShape'; points: [number, number][]; closed: boolean; segKind: SegKind; dir?: 1|-1 }` を追加（`addSegment` は2点の addShape として残す）。`removeSegment` は図形まるごと消す（`removeShape { group }` を追加し、removeSegment は id → group に読み替え）
- `HitEvent` に追加:
  - `group`, `segKind`
  - `chain`: そのボールが直前の衝突から 120 ステップ以内に **別の図形** に当たったら +1、そうでなければ 1
  - `energy`: 直近 2 小節（sectionSteps の 1/4）の衝突数 / 24 を 0..1 にクランプした値（決定論）
- `segmentAdded` を図形単位にする: `{ kind: 'shapeAdded'; step; group; segKind; note; midi; segments: Segment[] }`（`midi` は追加したステップの区間の音高 → 確定音に使う）。`segmentRemoved` は `{ kind: 'shapeRemoved'; step; group }`
- 新しいイベント: `{ kind: 'section'; step; section }`（区間の切り替わり。開始時にも1回出す）→ パッド用
- 回転は `segmentPose` を `shapePose { group, ... }` にして、描画は図形の重心と各頂点の相対座標から姿勢を作る

## D15. 各担当の範囲
- 物理: D12〜D14 の sim・scene・テスト
- 音: 確定音 `confirm(midi, time)`、ティック `tick(midi)`、パッド `setSection(section, time)`、energy による明るさ・ディレイ量・オクターブ上の重ね、バンパーの音色、ミュート `setMuted(on)`
- 映像: 弦が鳴る、連鎖の光（chain ≥ 3 で尾を強く、≥ 5 で通った図形を順に光らせ直す）、共鳴、energy でブルームを少し強く、放出口の呼吸、図形の描画、ツール入力（ペン・図形・Shift バンパー）、ドラッグ中のプレビュー音程の変化をコールバックで通知
- 統合（main）: ミュート（M キー＋GUI ボタン）、ツール選択の GUI とキー、配線、README

## ステップ4 統合時の補足
- ミュートは内蔵音と MIDI 出力の両方を止める（録音は続く）
- ティック音の音高は、ドラッグ中のスロットを今の区間で `midiAt` したもの
- 同じ時刻に確定音が重なる場合（配置の読み込みなど）は1回だけ鳴らす（Tone は同時刻の再発音で例外を投げるため）
- 閉じた図形が画面からはみ出す場合は、点ごとにクランプせず全体を平行移動して収める（形が潰れないように）
- 三角と四角は、右へ水平にドラッグしたとき頂点が上／辺が水平になる向きにする
- 当たった瞬間の大きな丸い滲みはブルームの低解像度段によるもので、ステップ3以前からある（今回むしろ小さくなった）。調整は投影で見てから

# ステップ5の裁定: 図形ごとの楽器

作者の選択: **図形の形で楽器が決まる**（楽器を選ぶキーは足さない）、**キック（円）は拍にそろえる**。
参考にしたアンビエントの定石: キックは「押し出す」より「鼓動」— 高域を落とした丸いアタック、リバーブは薄く。打楽器はリズムより質感として小さく散らす。低・中・高で音域を分けて濁らせない。

## D16. 形と音色
| 形 | 音色 | 音高 |
|---|---|---|
| line | 今の FM ベル（旋律） | midiAt(スロット, 区間) |
| pen | はじく音（カリンバ／撥弦） | midiAt |
| circle | 柔らかいキック〜タム（MembraneSynth 系、ローパス、リバーブ薄め） | **kickMidi**: 区間の根音。大きい円ほど低いオクターブ（C1 / C2 / C3 帯） |
| triangle | 金属（トライアングル／チャイム／シンギングボウル）、余韻長め | midiAt（高めのオクターブに寄せてよい） |
| square | 木・クリック（ウッドブロック／リム）、短い | midiAt |
- バンパーは今までどおり、どの形でもアタックを強めて重ねる
- 形は `ShapeForm`（`src/sim/types.ts`）。sim の図形・HitEvent・shapeAdded が持つ。推定は `src/sim/form.ts` の `inferForm`
- 確定音（D11）も形の音色で鳴らす。ティック（描いている途中）は今のまま
- 光も形で性格を変える（1:1 は保つ）: circle = 図形全体が脈打つ＋輪が広がる、triangle = 細かくきらめいて長く残る、square = 短く鋭い閃光、line / pen = 今の弦の震え（D44 で triangle / square にも形の輪を足した）

## D17. キックを拍にそろえる（決定論、sim で行う）→ **D22 で取りやめ**
- circle に当たったら、衝突は物理的には今までどおり（跳ね返りはその場）。**鳴らすのは接触ステップ以降の最初の拍の頭**（ちょうど拍の頭ならそのステップ）
- 拍の格子: `harmonyAnchor + round(k · HZ · 60 / bpm)`（テンポ変更・読み込みで取り直す基準と同じ）
- sim は保留キックを持ち、その拍のステップで HitEvent を出す: `step` = 拍のステップ、`contactStep` = 接触ステップ、x, y は接触位置。chain・energy は接触時に計算
- **同じ circle は1拍に1回まで**。同じ拍に複数当たったら1つにまとめ、velocity は最大
- 図形が消えたら（removeShape / clear / loadScene）その図形の保留キックも捨てる
- main・audio・MIDI・録音・描画は `step` だけを見ればよい（今までと同じ流れ）

## D21. D17 の見直し: 当たったら鳴らし、拍の頭は「こだま」にする → **D22 で取りやめ**
作者の感想: 拍まで待つと「当たって鳴る」感じがなく、ただ置いてあるだけに見える。エコーやディレイの結果として拍にそろうなら納得できる。
- circle も当たった瞬間に鳴らす（音・光ともに。ボールも光る）。D17 の保留とまとめ（1拍1回）はやめる
- そのあと、接触より後の拍の頭で **こだま** を ECHO_COUNT（2）回返す。velocity は ECHO_DECAY（0.5）の累乗で弱く、音量もさらに 1 回ごとに −4dB
- 同じ円にまた当たったら、残りのこだまは捨ててその音から数え直す。図形が消えたらこだまも捨てる。テンポを変えたら残りを新しい拍の格子に取り直す
- `HitEvent.echo`: 0 = 当たった音、1.. = こだま。こだまの区間と音高は鳴らすステップで決め直す。chain・energy には数えない
- こだまは内蔵音と光だけ（図形の脈と輪、弱く）。**MIDI・録音には当たった音だけを送る**（DAW 側のディレイに任せる）

## D25. 衝突で蔦が伸び、花が咲く

- 見た目だけの効果で、sim・音には関わらない（蔦は `src/render/vines.ts`、花は `src/render/flowers.ts`）。光の小窓の flowers で切り替える（既定はオン）
- 衝突した点から図形に沿って両側へ蔦が伸び（220px/s、片側 90 + 320·強さ px、閉じた図形は半周まで）、線をまたいで巻きつくように揺れる。通ったところに花が順に開く（「豪快に」）
  - 当たった所に大きな1輪（1.6倍）。蔦に沿って約 70px ごとに房（大小 1〜3 輪）。開くときに少し行き過ぎてから落ち着く（明るさは上げない）
  - 同じ図形では 0.4 秒に1本まで。衝突の強さ 0.1 以上・バンパー以外
  - 花は開いて 2.4 秒残ったあと茎を離れ、揺れながら回って（いろいろな角度から見える）下へ落ち、消えていく。蔦は花が離れると消える
  - 回る図形に付いた花は、落ちるまで図形にくっついて一緒に回る（位置だけでなく向きも。最初は向きを保っていて、図形から浮いて見えた）
  - 落ちる時間は長め（ゆっくり落ち、約 12 秒かけて消える）
  - 根本から咲く: 小さな蕾が蔦から外へ（花の大きさの約 0.7 倍）伸びながら、大きく育って開く。付け根から左右に葉が2枚出て、花はその間から伸びる（最初は茎を細い線で描いたが、葉のほうがよかった）
  - 散る: 花びらは 0〜0.7 秒ずれて1枚ずつ離れ、少し外へ広がり、自分の軸でひねりながら、少しずつ違う速さで落ちる（花芯は花と一緒）
  - 葉: 蔦に沿って約 34px ごとに左右交互に出る（伸びる向きへ少し倒す）。先が尖り、中央の筋で V 字に折れ、先が少し垂れる3Dの形。花と一緒に落ちるが、ひらひらと遅め
  - 花の半径は (39 + 27·強さ) × 0.35〜1.4 px（最初は小さすぎて、スマホでは形が分からなかった）
- 花は3D: 花びらを1枚ずつ曲面にし、蕾から開く。花ごとに傾き（正面〜ほぼ真横）と向き（線の外側）が違い、面の向きで明るさが変わる
- 花の形は1輪ごとに12種類からランダムに選ぶ（同じ図形の中でも違う花が咲く）: ひなぎく・桜・チューリップ・ゆり・睡蓮・菊・釣鐘草・星形（クレマチス）・薔薇・梅・たんぽぽ・風車（コスモス）。種類ごとに花びらの数・幅・開き方（平ら〜杯形）・反り・切れ込み・尖り・2重かどうか・花芯の大きさの範囲を決め、その中で揺らす（`FORMS`）
  - 色の系統は図形ごと（group から決まる）。図形の色（音程の色）から色相をずらし、1輪ごとに少し揺らす。輝度をそろえる（緑や黄だけ白飛びしないように）。white モードでは色を淡く（彩度 0.2、芯 0.1）、そのぶん明るくしてはっきり見せる（輝度 0.42、芯 0.5）→ **D37 で white / 音程ごとの切り替えはなくなった**
  - 最初は図形ごとに形も1種類に決めていたが、同じ図形でも形が違うほうがよかった
  - 閃光は出さない（最初の版は開く瞬間に光らせたが、チカチカした）
- 描き方（多数を出せるように）
  - 花びらは板のインスタンス（花1輪 = 花びら数 ×1〜2 + 花芯）。形・開き・傾き・明るさは頂点シェーダが咲いた時刻からの経過で決める
  - CPU は咲いたときにリングバッファ（49152枠）の枠を書いて、その範囲だけ送る（`addUpdateRange`）。毎フレームの書き換えはなく、回る図形の花の位置だけ直す
  - 加算合成なので奥行きの並べ替えは不要。`discard` は使わない（タイル型のモバイル GPU で遅くなるため）
  - WebGPU / TSL への移行は見送る: EffectComposer と ShaderMaterial / onBeforeCompile がすべて書き直しになり、古い iOS や多くの Android では WebGL2 に落ちるため。粒の相互作用を 10万単位で計算したくなったら再検討

## D27. 描画を軽くし、重い端末では自動で画質を下げる

- 測ってわかったこと（PC の Chrome で計測）
  - 重いのは後処理（MSAA 4倍・グロー・残像）で、それぞれ 1フレーム 7〜10ms 前後。花の数そのものはほとんど効かない
  - 毎フレーム、全部のインスタンス用バッファを上限の大きさのまま GPU に送っていた（約 1.9MB/フレーム）
  - 蔦の描画が CPU では一番重い（四角形 1枚ずつ Object3D で行列を作っていた）
- 送るのは書いた先頭 n 個だけにする（`addUpdateRange`）→ 約 72KB/フレーム。花の位置直しも動いた範囲だけ
- 線の四角形は行列を直接書く（蔦の描画が約 1/2.5）
- 解像度の設定が後処理に効いていなかった（EffectComposer は作ったときの倍率のまま）ので、後処理も同じ倍率で描く
- 自動の画質: 2秒ごとに平均のフレーム時間を見て、48fps を下回っていたら1段下げる。MSAA 4 → なし → 後処理の解像度 0.75 → 0.6。上げ直すと行き来してちらつくので上げない（解像度の設定を変えると測り直す）→ D67 で、待ちを延ばしながら上げ直すようにした
  - 0.1 秒以上の止まり（タブ切り替えなど）は数えない
  - iPhone の低電力モード（30fps 固定）でも下がってしまうが、害は小さいのでそのままにする
- `?fps` を URL に付けると、右下に fps と画質の段階（q0〜q3）を出す。実機で確かめる用

## D29. 音の時計で固まらないようにする

- ときどき 1〜2 秒画面が止まっていた。計ってみると、止まりはすべて毎フレーム呼んでいた `AudioContext.getOutputTimestamp()` の中だった（Chrome では音声スレッドのロックを待つので、音声側が忙しいと戻ってこない）
- 毎フレームはロックの要らない `currentTime` だけを読む。`currentTime` は音声の処理の区切りごとに飛んで進むので、performance.now で先へ進めつつ、ずれを少しずつ寄せてなめらかな時計にする（0.1 秒以上ずれたら合わせ直す）。`src/audio/clock.ts`
- 出力の遅れ（`outputLatency`、なければ `baseLatency`）は開始時と 1.5 秒後の2回だけ読む
- 見た目と音がずれて感じたら、設定の visual offset で合わせる

## D30. 再生・停止（止め方は D50 で変えた）

- ツールバーの左端のボタンと Space キーで止める・続ける
- 止めるときは AudioContext ごと `suspend()` する。音の時刻が止まるので、sim も（時刻から進める量を決めているので）描画も自然に止まる。続けると同じ時刻から進むので、`t0` を取り直さなくてよい
- 止めている間も描画は経過時間 0 で続ける。絵（残像も）は止まったまま、描きかけの線は見える
- 止めている間も図形は置ける・消せる。sim の時刻は進めずに編集だけを今のステップで反映し（`Sim.applyPending`）、描画も renderStep を待たずにすぐ反映する（`Renderer.applyEditsNow`）。消す図形は、描画の時刻が止まっているので消える動きなしで消す。置いた音は鳴らさない
- MIDI は止めたときに全部 note off を送る

## D31. 当たった図形から光が垂れる（drip）

- 残像（AfterimagePass）を自前の `FlowPass`（`src/render/flow.ts`）に置き換えた。`drip`（光の小窓、既定オン）では、明るいところ（輝度 0.45〜0.95 で入り始める。ボールや当たった光）だけを残像に入れ、前の絵を少し上から読んで重ねるので、当たった図形から光が垂れて流れ落ちる
  - 流れる速さは数 px 幅の列ごとに違い、横にゆらぐ（水の筋に見えるように）。前の絵は線形補間で読むので、流れた光は縦に少しにじむ
  - 流れた光は 55% の明るさで見せる。`drip speed`（px/s、既定 90）
  - 全部を流すと線や花の下にいつも幕が垂れて重かったので、明るいところだけにした
- オフなら今までの残像と同じ見た目
- 止めている間（D30）は経過時間 0 なので、流れも止まる
- 試してやめたもの: ボールの軌道を残し続けて滝に見せる（trace）。軌道は線として残ったが、滝に見えるにはボールの数がずっと多く要る。ボールは音符なので増やせず、音を鳴らさない水滴のボールを別に流す案も出たが、いったん見送った

## D32. 図形ごとのエフェクト

D22 で「あとで足す」とした、図形に掛けて当たったあとどうなるかを決める機能。1つの図形に1つ。
- **echo**: 当たった音を、そのあとの拍の頭で3回くり返す（velocity は 0.55 の累乗）
- **rise**: 半拍ごとに音階を1つずつ上がりながら4回くり返す（velocity は 0.8 の累乗）。circle は1帯（5スロット）ずつ上がり、キック → タムになる。一番上で止まる
- **chord**: 同じステップにペンタトニックで2つ上・3つ上の音を重ねる（velocity ×0.7）。circle は1帯・2帯上。上に収まらない音は下に取る
- くり返しは D21 と同じく sim が決める（決定論）。最初のくり返しは、格子の半分以上あけた次の格子で鳴らす（当たった音とくっつかないように）。同じ図形にまた当たったら残りを捨てて数え直し、エフェクトを変えた・図形を消したら捨てる。テンポを変えたら残りを新しい格子に取り直す。区間と音高は鳴らすステップで決め直す
- `HitEvent.echo`（0 = 当たった音、1.. = くり返し）と `voice`（0 = 本体、1.. = 重ねた音）。chain・energy・花・波紋・ボールの色には数えない。くり返しは図形が弱く光る。重ねた音は光らせない
- D21 と違い、**MIDI・録音にも全部送る**: rise と chord は DAW のディレイでは作れない音なので
- 操作: 図形を長押し（マウスは右クリック）すると、押した場所のそばにメニューが開く: echo / rise / chord / delete。選ぶと付き、付いているものを選ぶと外れる。止めている間（D30）も付けられる。はじめはツールバーの fx ボタン（道具 + 小窓で種類を選んでからタップ）にしたが、道具を持ち替える手間が多く選びにくかったので、図形から直接選ぶ形にした。長押し・右クリックはこれまで「すぐ消す」だったが、消すのもメニューの delete に移した（1手増えるが、誤って消すことも減る）
- 見た目: 光る線が何重にも取り囲む等高線のような絵を参考に、エフェクトの付いた図形はまわりに淡い輪郭を何重かまとう。種類が見て分かるように動きと色を変える: echo は同じ色の輪が外へ流れて消えていく（波紋）、rise は同じ形が上へ昇りながら消えていき、色は上がっていく音の色、chord は動かない点線の輪郭を重ねる音の色で2本（色の出ない mono でも点線で分かるように）。開いた図形（線・ペン）では echo と chord は両側に平行に、rise は上側だけに出す。当たるたびに輪郭が外へ広がる（rise は上へ昇り、chord は重ねる音の色で）。種類の印（◎ など）を図形の真ん中に出すことも試したが、不要と判断して外した。輪郭は待機の線より明るく太めにして、スマホでも見えるようにする
- 保存: `SceneData.effects`（shapes と同じ順）。エフェクトが1つもなければ書かない。無い・長さが合わない・不正な値は none

## D33. 背景の光の膜

- 光（Light）の water で選ぶ（none / caustics / particles / grain。none が既定）。water level で明るさ。切り替えはいったん暗くしてから次へ → **D45 で backdrop / level に改名**。種類は D38〜D43 で増えた
  - 種類ごとに BackdropLayer（render/caustics.ts, render/particles.ts, render/grain.ts）を作り、render/backdrop.ts が切り替える
- 光線の格子（横の線 320 本）を、うねる面の傾きで曲げ、行き着いた先に細い線を引く（水面を通った光が壁に映る模様のつくり）
  - 線は加算で重ねるので、光が集まるほど明るく、膜が折れ重なったところに明るい尖りができる
  - 線の位置と明るさを1本ずつばらつかせる（そろえると網目・縞に見えた）。縦の線は網目に見えるので引かない
  - 全面ではなく中央にまとまり、縁は不規則に消える。膜ごとに明るさが違い、いくつかの膜が浮かぶように見える
- 音に反応して形を変える: 当たるたびに、当たった点に対応する面から輪が広がって膜がゆがみ、折れ（屈折の強さ）が一瞬強くなる。輪のところに音の色が少し混ざる。盛り上がり（energy）で折れが強く、動きが速くなる
- 形は頂点シェーダーで計算する（CPU は当たりを覚えるだけ）。時刻は renderStep から取るので、止めると膜も止まる
- 試して見送った案: 全面に敷くシェーダー（水底の網・水面・光の筋）、塗りのかたまり、閉じた線の重なり、膜 4 枚の重ね、線の毛玉、光の筋が結び目に集まる形。この1枚の膜がいちばん綺麗だった

## D34. 背景の粒子の流れ（particles）

- TouchDesigner でよく使う「GPU の粒子 ＋ フィードバック」のつくり（他の候補: 反応拡散、フィードバックの渦、インスタンシング、スリットスキャン、データモッシュ）
- 粒子 160×160 個の位置を GPU のテクスチャ（半精度、範囲の半径を 1 とする座標）に持ち、渦を巻くノイズの流れ（curl noise）に乗せて動かす
  - ゆっくり漂う湧き出し口 2 つのまわりで広めに生まれ（大きなまとまりにする）、流れの範囲は見えている範囲の短いほうの半分、寿命（3〜7 秒）が来ると生まれ直すので、いくつかの塊の流れになる。外へ出すぎると中へ戻す
- 動いた分を細い線で専用のバッファ（画面と同じ大きさ）に描き足し、バッファは少しずつ薄くする（フィードバック）。軌跡が絹や煙の筋になる
  - 重なって明るくなりすぎたところは頭打ちにする（ブルームで画面全体がかすんだ）
- 音に反応する: 当たるたびに、当たった点から粒子が噴き出し、そのまわりの流れを押しのけて渦を作る。当たった点のそばの筋はその音の色になる。盛り上がり（energy）で流れが速くなる
- 止めている間は動かさず、薄くもしない（そのまま止まる）

## D35. 背景の粒（grain）

- TouchDesigner の作品「Trajectory」（点の集まりで形を見せる描き方）を参考にした。粒 65536 個を1粒ずつ点（0.8 CSS px）で描き、色は色の設定によらず白黒だけ、形は点の混み具合で見せる
  - 点は毎フレーム少し瞬く（フィルムの粒）。瞬きも時刻から作るので、止めると止まる
- 粒は画面全体に均等に散らばり、ふだんはそれぞれの場所のまわりを少しだけ動く（数 px。速さ・向き・大きさは粒ごとにばらばら。盛り上がりで少し大きく動く）。同じ位置で止まっていると固く見えた
- 音が当たると、その近くの粒同士が寄り集まって形になり、音が消えると元の場所へほどける（0.12 秒で寄り、0.35 秒保ち、2.2 秒でほどける）
  - 形は当たるごとに、当たった点を囲む揺らいだ輪か、当たった点を通る短い線（向きは毎回変わる）
  - 形の大きさは音の高さで変わり（高いほど小さく締まる）、寄せる範囲は当たりの強さで広がる。寄った粒は明るくなる
  - 重なった当たりは重みで平均するので、近くで続けて鳴ると形が混ざる
- 粒の状態は持たず、元の場所（粒ごとの乱数）と当たりの記録から頂点シェーダーで位置を計算する
- 見送った案: ねじれたリボン（軌道の後ろに残る粒）、音でたまる「集まり」で全体が1つの形にまとまる動き（音と結びついて見えず、いつもまとまっているように見えた）
- 当たった点の計器の表示は背景から分けた（D36）

## D36. 当たった点の計器の表示（hud）

- D35 と一緒に作ったが、どの背景とも組み合わせられるよう別にした。Light の hud でオン・オフ（既定はオフ）
- 当たった点に、正方形の細い枠（角の括弧か枠線。真ん中に小さな正方形）と座標の数字 (X … Y …) が点滅して出て、1.6 秒で消える。丸（楕円）や十字はやめて正方形にそろえた
- 続けて当たると前の表示と細い線でつながる。出すのは 0.2 秒に1つまで（同時に最大 6 つ）。枠の大きさは当たりの強さで変わる
- 色は背景と同じ基の色。時刻は renderStep から取るので、止めると止まる

## D37. 色は白黒（mono）だけ

- 色の設定（by pitch / white）をやめて、いつも白黒（mono）で描く。背景の粒（D35）と合わせて、全体を白黒の見た目にそろえる
- メニュー（Light の popover とパネル）から color を外した。保存してある設定に 'pitch' が残っていても読まない（colorMode は設定として保存も読み込みもしない）
- 音の高さで色を付けるコード（palette の 'pitch'）は残してあるが、使わない

## D38 背景の網点（bitmap）
- 背景に bitmap を足した。画面を正方形の升目（11 CSS px）に分け、升目ごとに角の丸い四角の点を置く。点の大きさで濃淡を見せる網点（一度丸にしたが、四角に戻した）
- 濃淡の場は、ゆっくり流れる低い周波数のノイズと、当たった点から広がる丸いにじみの和。濃いほど点が大きくなり、隣とつながってぼやける
- にじみの大きさは強さで、広がる速さと大きさは音の高さで変わる。3.2 秒で消える
- 場は升目の真ん中の値だけを使うので、なめらかな場が段々の点で見える。全画面の1枚の四角をフラグメントシェーダーで描き、状態は持たない
- 色は青の濃淡。薄いところは暗い紺の小さな点、濃いところは青から明るい水色へ。D37（色は白黒だけ）の例外で、この背景だけの色 → **D57 で白黒にした**

## D39 背景の文字の網（ascii）
- 背景に ascii を足した。画面を縦長の升目（9×14 CSS px）に分け、升目ごとに文字を1つ置く。文字は濃淡の場で決まる（薄い ` . : - = + * # % @` 濃い）
- 濃淡の場は、ゆっくり流れるノイズと、当たった点のにじみの和。ノイズは薄めにして、何もない所を残す
- 音が当たると、そこから細い輪が広がる。輪の上の文字は、でたらめな文字（`0 1 < > / \ | [ ] { }`）に入れ替わりながら明るく光る。輪の広がる速さは音の高さで変わる（高いほど速い）。2.6 秒で消える
- 文字は canvas に並べて描いた1枚のテクスチャから取り、全画面の1枚の四角をフラグメントシェーダーで描く。状態は持たない
- 色は白黒だけ（D37）

## D40 モバイルで開始直後に落ちるのを防ぐ（声部と背景を必要になってから作る）
- 症状: スマホで開いてタップした直後にページが再読み込みされる（メモリ不足でタブが落ちる）
- 原因: 開始時に音の声部（FM シンセなど約50個）をまとめて作っていた。Tone のシンセは中に多くのノードを持つので、開始の瞬間に約2200個のノード（うち常に動く ConstantSource が約700個）ができ、メモリが一気に跳ねていた
- 声部は種類ごとの置き場に入れ、空きがないときだけ上限（今までの数）まで新しく作る。開始時のノードは約400個になった。よく鳴らすと上限まで増えるが、少しずつ増えるので一度に跳ねない
- 背景（D33）も、全種類を最初に作るのをやめ、選んだ種類だけ作り、外したら捨てる

## D41 ページを離れたら音を止める
- 症状: スマホで Safari を離れても、パッドの音だけ鳴り続ける（図形の音は止まる）
- 原因: 図形の音は描画のループ（rAF）から鳴らすので、隠れると自然に止まる。パッドは AudioContext の中で鳴り続けるので止まらなかった
- 隠れたら（visibilitychange / pagehide）AudioContext ごと suspend する。一時停止（D30）と同じく時刻も止まるので、戻ると同じところから続く
- 戻ったら、自分で一時停止していなければ resume する。iOS は戻ったとき interrupted のままのことがあるので pageshow でも resume し直す

## D42 3D の背景（fibers / slices）
- 背景に 3D の見た目の 2 種類を足した。どちらも立方体（-1..1）を見えている範囲の真ん中に置き、アイソメトリック（平行投影、縦軸まわり 45°・見下ろし 35.26°）で見る（cube.ts に共通のカメラと 3D のノイズ）
  - はじめは透視のカメラで斜めから見て、ゆっくり回していたが、奥行きの向きがわかりにくかった。3 つの面が同じだけ見える決まった角度にして、回さない
- 当たった点は、立方体の真ん中を通って画面に平行な面に落とし、立方体の中の座標にする（fibers で使う）。そこから球の波が広がり、波の広がる速さは音の高さで変わる（高いほど速い）
- 流れの進み具合は「時刻 × 速さ × (1 + 盛り上がり)」ではなく、フレームごとに足していく。掛け算だと、盛り上がりが変わった瞬間に流れがとぶ（時刻が進むほど大きくとぶ）
- fibers（流線）: 立方体の中の curl noise（湧き出しのない、渦を巻くノイズの流れ）の流線を、細い筒で描く。3D の流れ場の見せ方として定番の表現
  - 12×12×12 の升目の点から、流れに沿って前後にたどった線（16 節）。18×18×18 では線が多くごちゃごちゃしたので、数を減らし、線を長く太く、流れの模様を大きく（細かい渦を弱く）した。近い線はそろって流れ、束になって波打つ。流れの向きが見る向きと重なる所では、線の端が升目の点に見える
  - 線の形は毎フレーム GPU でたどり直す（線ごと・節ごとに 1 テクセルのテクスチャ、中点法）。線は画面に向けた細い帯で、インスタンシングで 1 回で描く
  - 光は線の向きで決める（髪の毛の当たり方）。筒の真ん中が明るく、奥ほど暗い。立方体の外に出た所は切る（はみ出したままだと球に見えた）。奥の線が手前に隠れるよう、専用のバッファ（CSS px の 1.5 倍まで、MSAA 4）に深さつきで描いてから画面に足す
  - はじめは短い毛を升目に並べて流れの向きに寝かせていたが、毛がばらばらで流れに見えなかった
  - 明るすぎると図形が見えなくなるので、背景として暗めに抑える（明るさ 0.38）
  - 当たると、波の通る所の流れが外へ押されて線がなびき、明るくなる。止めている間は描き直さない
- slices（時間のスライス）: TouchDesigner の Texture 3D TOP（動く画像を毎フレーム貯めて、インスタンスした板に1枚ずつ並べる）のつくり。12 枚の板の、手前の板に今の雲、奥の板ほど少し前（1 枚 0.35 秒）の雲を映す。雲の動きが手前から隣の板へ、奥へと伝わっていく
  - 画像を貯める代わりに、雲を「時刻を入れると形が決まる」ノイズ（fbm）にして、板ごとに遅らせた時刻で計算する（状態もメモリも持たない）
  - 雲は真ん中ほど濃く、奥の板（古い雲）ほど少し薄い。板の縁は細い線、面はフィルムの粒のようにざらつく。光を足すだけなので深さは使わず、画面に直接描く
  - 当たった点には反応しない。盛り上がり（energy）で少し濃く、速く変わる
  - 試して見送った案: 立方体の 3D の雲を板ごとの位置で切った断面（隣の板の模様が違うだけで、動きが板を渡らない）、当たった点からの球の波（うるさかった）、雲が横へ流れる動き
- 色は白黒だけ（D37）。時刻は renderStep から取るので、止めると止まる

## D43 背景のノイズの塊（volume）
- 背景に volume を足した。線だけの立方体（辺と角の点）の中に、3D のノイズの塊を点の集まり（15 万点）で描く
- 塊の形は「濃さ = ノイズ（傾きもわかる値のノイズ 2 段）+ 真ん中ほど濃い」が 0 になる面（等値面）。ノイズがゆっくり変わるので、塊がうねる
  - 点は立方体の中にばらまいた場所から、傾きの向きに 2 歩で面へ寄せる（ニュートン法）。寄りきらなかった点と、立方体の外に出た点は使わない。面の近くの点だけを残すやり方ではまばらで、雲にしか見えなかった
  - 点の明るさは、面が見る向きに向いているほど明るく、奥ほど暗い。点ごとに少しばらつかせて、ざらついた膜に見せる
- 音に反応する（2.4 秒で戻る。大きさは音の高さで変わり、低いほど大きい）
  - 当たった点のまわりの濃さが増えて、膜がふくらむ
  - そこの点が面の外向きにはじける（すぐ出て、ゆっくり戻る。飛ぶ距離は点ごとにばらつかせ、遠いものは立方体の辺の半分の 0.6 くらいまで飛ぶ）
  - 盛り上がり（energy）で塊が少しふくらみ、速く変わる
  - はじめは膜がふくらむだけだったが、ほとんど見えなかった。はじけて光る・光の輪が広がる・盛り上がりで明るく脈打つ、も試したが、光りすぎたので、光らせず動きだけにした
- 立方体は平行投影で、アイソメトリックから少しずらした角度で見る。ちょうどアイソメトリックだと、線だけの立方体は手前と奥の角が重なって形がわかりにくかった
- 光を足すだけなので深さは使わず、画面に直接描く。色は白黒だけ（D37）。時刻は renderStep から取るので、止めると止まる

## D44 三角・四角の形の輪

- 円は当たると重心から円の輪が広がるが、三角・四角には図形全体で分かる光がなく（打点の小さな波紋ときらめき・閃光だけ）、形の違いが見えにくかった
- 三角・四角も、当たると重心から**図形と同じ形・同じ向きの輪郭**が広がる。向きは最初の頂点の向き（回っている図形は当たった時点の角度）
  - square（木）: 短く速く弾け出る（0.35 秒、半径の 35% + 14px）
  - triangle（金属）: ゆっくり広がりながら 0.35rad 回り、長く残る（1.6 秒、半径の 70% + 24px）。回る向きは図形の回る向き、止まっていれば当たるごとに交互
- 輪の辺の太さは円の輪（半径の 7%）とそろえる。確定音・くり返し（echo / rise）でも出る（円と同じ）。今までの打点の波紋・きらめき・閃光はそのまま

## D45 UI を整える（白黒・小見出し・案内）

- UI の色と文字の大きさを index.html の `:root` の変数（`--ui-*`、`--fs*`）にまとめた。ツールバーの見た目は `src/ui/toolbar.css` に移し、パネル（panel.css）も同じ変数を使う
- UI でも赤をやめて白黒にそろえた（D37）。ミュートはアイコン（×）と白、図形メニューの delete は区切り線だけ、MIDI の録音中は白の点滅で見せる
- 光の小窓を小見出しで3つに分けた: shapes（glow・lines・trail）/ on hit（drip・drip speed・flowers・hud）/ backdrop（kind・level）。わかりにくかった「water」は backdrop に改めた（設定パネルも）。オフのものに付くつまみ（drip がオフの drip speed、背景が none の level）は薄くする
- motion のアイコンを、再読み込みに見えた回る矢印から、軌道と玉の形に変えた
- タッチではツールバーのボタンを 40px にした（これまで 34px で押しにくかった）。保存した配置の削除ボタンも、タッチでは常に出す
- 開始画面の上にツールバーが透けて見えていたので、開始画面を前に出した。操作の案内（画面下）は始めてから 12 秒だけ出して消す（キーは `<kbd>` で少し明るく）

## D46 設定パネルを整理し、タッチでも開けるようにする（開き方は D52 で小窓にそろえた）

- ツールバーに設定ボタン（スライダーの形）を足し、`,` キーと同じくパネルを開閉する。D24 ではキーボード専用だったが、スマホでも pattern・pad・MIDI などを触れるようにした。パネルの上に見出しと × を置き、幅 640px 以下では画面の幅いっぱいに開く
- ツールバーの小窓と同じつまみはパネルから外し、小窓にないものだけを置く
  - Sound: pattern・pad・pad level・stereo
  - Motion: sway style（drift / phrase）。回る速さと揺れの大きさ、オフは motion の小窓 → D47 で motion の小窓へ移し、パネルからは外した
  - Display: trail の方式（geometry / afterimage）・light delay・resolution。glow・lines・trail の長さ・背景は light の小窓
  - MIDI（畳んで開く）
  - Keys: キー操作の一覧（マウスのある端末だけ）。画面下の案内は 12 秒で消える（D45）ので、ここでいつでも見られる
  - reset settings
- 名前だけでは何が変わるかわからなかったので、sway style と Display の各行の下に小さな説明（`Section.hint`）を付けた。選んでいる値に合わせて文が変わる
  - sway の選択肢は drift / phrase から glide / step に、trail の方式は geometry / afterimage から tail / blur に表示名を変えた（保存する値は変えない）
  - blur のときは残像の長さが決まっている（LEGACY_DAMP）ので、光の小窓の trail つまみを薄くする

## D47 動きを止められるようにする

- これまでも spin と sway を両方 0 にすれば止まったが、止めるための操作に見えず、戻すときに元の値もわからなかった。motion の小窓の一番上に move のスイッチを置いた
  - オフにすると回転と揺れを両方止める。オンに戻すと、止める前に回っていたかと、最後に選んだ揺れ方に戻す（揺れの大きさ・回る速さは止めても残っている）
  - どちらかのつまみを 0 より上にすると move もオンになる（つまみを動かすと、小窓のほかの行の表示も合わせる）
- 揺れ方（sway style: glide / step）も、パネルから motion の小窓の sway の下へ移した。動きのことは小窓にまとめ、パネルの Motion の区分はなくした
- 止めた状態は配置と一緒に保存される（rotate と drift が off になるので。止める前の値はページを開き直すと忘れる）

## D48 曲を選べるようにする（pad を backing chord に）

- 和音の進み方が C–F–C–G（I–IV–I–V）の1種類しかなかった。Sound に song を置き、進み方・調・後ろの和音の音色をまとめて選べるようにした（`sim/music.ts` の `SONGS`）
  - bright: C–F–C–G（これまでと同じ音）/ dusk: Cm–A♭–E♭–B♭（短調）/ wistful: F–G–Em–Am（IV–V–iii–vi）/ still: C のまま変わらない
  - どの曲も4区間・各区間5音の音階なので、区間の数え方やスロット（線の長さ → 音）はそのまま。隣り合う区間で同じスロットの音が3半音より跳ばないように音階を選んだ（テストで確かめる）
  - 図形の音（MIDI も）・キックの根音・後ろの和音がすべて曲に従う。曲は sim が持ち、配置と一緒に保存する（bright のときは書かない。古いリンクは bright で読む）
  - 曲を変えると次のステップから新しい音階になり、後ろの和音は新しい根音へゆっくり移る（区間のイベントに根音 `root` を載せ、audio はそれを見る）。曲ごとに和音の明るさ（ローパス）を変える
- 「pad」では何の音かわからなかったので、表示を hum / hum vol にし、説明を付けた（backing chord はスマホで名前が切れ、chord はエフェクトと重なった。D49）。オフのときは level を薄くする（保存する値の名前 pad / padLevel は変えない）
- 曲の選択肢には説明を付けない（名前で雰囲気がわかれば十分）

## D49 名前だけでわからない設定に説明を足す

- Sound の pattern を rhythm にし、下に「いくつの口から、何拍ごとに玉を出すか」を選んでいる値に合わせて書く（保存する値は変えない）
- 光の小窓: lines を at rest（当たっていないときの図形の明るさ）、drip speed を speed、hud を readout に表示名を変え、各行の下に何が起きるかを書いた。trail は tail のときだけ説明し、blur のときは設定の Display で選ぶことを書く
  - 説明を足して小窓が高くなったので、小窓の最大の高さを 360px から 560px にした（画面が低いときは今までどおりスクロール）
- 道具を選ぶと、ツールバーの下に名前と音色（例: circle — kick）を 1.6 秒だけ出す。タッチではボタンのホバーの説明が出ず、どの形がどの音か知る方法がなかったため（キーの 1–5 でも出す）
- Sound の後ろの和音は chord から hum / hum vol にした。図形のエフェクトの chord（和音を重ねる）と同じ名前になっていたため。drone も考えたが、drone は高さが変わらない音を指すことが多く、曲に合わせて根音が動くこの音には合わない
- song と hum が同じものに見えたので、つながりを説明に書く: song の下に「図形も含め、すべての音の和音が変わる」、hum の下に「song の和音を後ろで鳴らし続ける」

## D50 停止は球を出すのをやめ、ゆっくり止める

- D30 の停止は AudioContext ごと止めていたので、押した瞬間に絵も音も固まり、急に感じた
- 時刻は止めない。止めると
  - 球を出さなくなる。放出の番号は進め続けるので、続けると次の拍から元の拍の並びで出る
  - 回転は 2 秒かけて止まる（速さに 0..1 を掛け、なめらかに変える。1/30 秒ごとに角速度を置き直すので、角度は飛ばない）。続けると同じだけかけて戻る
  - 内蔵音は 3 秒かけて消える（master の gain）。続けると 0.6 秒で戻る
  - 落ちている途中の球はそのまま当たり、光る（音は小さくなっていく）。MIDI は止めたときに全部 note off にし、止めている間は送らない
- 止めている間も時刻が進むので、図形の追加・削除はふつうに反映される（D30 の `applyPending` / `applyEditsNow` はいらなくなったので消した）
- タブを隠したとき（D41）は、これまでどおり AudioContext ごと止める

## D51 sound を小窓に出し、display を分ける

- ツールバーの小窓（motion / light）は弾きながら触る作品の設定、settings は会場・端末に合わせて一度決める設定、と分けている
- rhythm・song・hum は曲そのものを変えるので、settings の奥ではなく小窓にした。ツールバーに音符のボタンを足し、motion / light / sound と並べる（ミュートのスピーカーと見分けがつくように音符にした）
- display はボタンにしない。中身を分ける
  - trail style は light の小窓へ（trail の長さと同じ場所に。これまでは「settings → display で tail にしないと効かない」と案内していた）
  - light delay・resolution は、sound から残した stereo と一緒に settings の Setup にまとめる
- ボタンが増えて狭いタッチ画面でツールバーが 3 段になったので、そこでは音量のつまみを隠した（本体のボタンで変えられる。ミュートは残す）
- 小窓も読み込み・リセット・テンポ変更のときに表示を合わせる（`Popover.refresh`）

## D52 settings もほかの小窓と同じ開き方にする

- settings だけ、画面の右端に固定され、見出しと × の付いたパネルで開いていた。`,` キー専用のパネル（D24）にボタンを足した（D46）名残で、開き方・閉じ方が 2 通りあった

## D53 操作の案内を、使える場面でだけ画面の下に出す

- 右クリック（タッチでは長押し）で図形のメニューが開くこと、Shift でバンパーになることは、始めに 12 秒出す一覧（D45）だけでは気づきにくかった。特に長押しは、知らないと試さない
- 操作しているときだけ、その場で使える操作を画面の下の真ん中に出す（`src/ui/hint.ts`）。指やカーソルのそばには出さない（手で隠れる・絵に重なる）
  - マウス: 図形に乗ったら「right-click effects / delete」、描いている間は「hold shift for a bumper」（押している間は「bumper」）
  - タッチ: 図形を 0.15 秒押さえたら「keep holding · effects / delete」と細い線を出し、線が満ちたところでメニューが開く。指が動いたら（描き始めたら）消す

- あわせて、図形のメニューの文字が行の上に寄っていたのを、行の真ん中にそろえた

## D54 メニューを開いている図形をゆっくり明滅させる

- 図形が重なっていると、右クリック・長押しでどの図形のメニューが開いたのかわからなかった
- メニューを開いている間、その図形を 1.6 秒の周期でゆっくり薄くして戻す（いちばん薄いところで 15%）。線だけ薄くしてもエフェクトの輪が残ると見分けにくいので、エフェクト（常に出ている輪と、当たるたびに広がる輪）も同じだけ薄くする。はじめは明るく・太くしたが、当たって光る図形が多いと見分けられなかったので、光らせるのではなく不透明度で見せる。開いた瞬間はいつもの濃さから始める
- メニューを閉じる（選ぶ・外を押す・Esc）と止まる

## D55 コード全体の点検（不具合の修正と分割）

- コード全体を読み直し、見つかった不具合を直してから、大きくなったファイルを分けた。見た目・音・操作は変えない
- 動きが変わった点
  - リンク（`#s=…`）で開いた配置は一度だけ読み、すぐ端末の保存に移して URL から消す。以前は S を押すと URL にリンクが残り、その後の編集がリロードで古いリンクの配置に戻っていた。S はアドレスバーを書き換えず、コピーできたかをツールバーの下（保存の小窓が開いていればそこ）に出す
  - 開始の二度押しで音の仕組みが二重にできていたのを、一度だけ作るようにした。始められなかったときは押し直せる
  - テンポの範囲を 40〜200 にそろえた（ツールバーは 60〜140、読み込む配置は 40〜200 で食い違っていた）。読み込み・リセットの直後に、押している途中のテンポが後から上書きしないようにした
  - 保存・削除に失敗したとき（容量がいっぱい・保存できない環境）は「saved」と出さず、失敗を知らせる。保存の小窓を開くたびに一覧を読み直す（別のタブで保存したものも出る）
  - スライダーを触った後もキー操作が効くようにした（文字を打つ欄だけ除く）。キーの押しっぱなしで繰り返さない
  - 配置を読み込んだ後の move のオン・オフで、読み込んだ揺れ方に戻る
  - MIDI: 同じ音が同じ時刻に重なったとき、1 tick で切れる音や閉じない音を作らない（ライブ出力と .mid の両方）
  - 後ろの和音: 切り替えが続いたとき、消えかけの層がプツッと鳴らないように一度小さくしてから高さを変える
  - 花を切って戻したときに、古い花びらが蔦なしで残らないようにした。花の番号が上書きされた後に別の花を動かさないようにした
  - 背景を切り替えるたびに素材（シェーダ）が残っていたのを捨てるようにした

## D56 型チェックを strict にし、リンターに Biome を入れる

- ライブラリは足さない（UI は約 1,900 行で、描画と音は three.js・Tone.js が受け持つ。UI の仕組みを入れても状態が二重になるだけ）。代わりに開発のときだけ使う道具で守りを固める
- tsconfig に `strict` と `noUncheckedIndexedAccess` を入れ、`test/` も型チェックの対象にした。これまで `strict` がなく、`!` や null の確認が型の上では何もしていなかった。入れても直す所は 4 か所だけだった
- リンターは Biome（`npm run lint`）。推奨のルールから `noNonNullAssertion` だけ切る（配列の添字で `!` を使う書き方をそのまま使う）。整形は今の書き方を保つために使わない
- 指摘で直したもの
  - 小窓のボタンの打ち消しを `:where()` で詳細度 0 にし、`!important` 26 か所を外した（計算後のスタイルは全要素で変わらない）
  - 3 つのファイルに同じものがあった `easeOutCubic` を `render/ease.ts` にまとめた
  - `Math.pow` を `**` に、`hasOwnProperty` を `Object.hasOwn` に

## D57 bitmap の色も白黒にする（D38 の例外をやめる）

- bitmap の網点は青の濃淡だった（D38 で D37 の例外にした）。ほかの背景と並べると、これだけ色が浮くので白黒にそろえた
- 色は暗い灰（`#303030`）→ 灰（`#9a9a9a`）→ 白。薄いところは暗い灰の小さな点、濃いところほど白く大きな点になる。明るさは青のときと同じくらい
- 花の色はそのまま（うっすら色づくのは残す）

## D58 音の途切れ（ブツッ）を減らす: 出力のまとまりを大きく
- たまに音がブツッと途切れる。実際の配置の 45 秒をオフラインで書き出して調べると、合成した波形には段差がなかった（声部の横取りは段差を作るが、この配置では横取りされる声部はほぼ鳴り終わっている）。途切れは再生中に音声の処理が間に合わないこと（バッファの不足）とみた
- AudioContext の `latencyHint` を `interactive`（Mac の Chrome で約 6ms）から `playback`（約 23ms）にした。音は先に予約しているので、遅れは描画・MIDI の時刻合わせ（D29）で吸収され、ずれない。ドラッグ中の音程の音（D11）だけ少し遅れる
- sim の先行（LOOKAHEAD）を 50ms → 100ms にした。出力のまとまりが大きい端末で、予約が間に合わずに捨てる音（LATE_DROP）が出ないように
- 実機で比べられるように、`?latency=0.05`（秒）や `?latency=interactive` で `latencyHint` を変えられるようにした。`?fps` の表示に音の遅れ（base / output、ms）も出す

## D59 聞こえない音を処理しない・声部の横取りで鳴るプツッを消す
- ミュート中と、停止して小さくしきった後（STOP_FADE_SEC）は、衝突・確定音・ティックの声部を鳴らさずに捨てる。今までは master の音量を 0 にするだけで、合成は続けていた
- hum を切ったら、小さくしきってから（1.5 秒）パッドの発振器を止める。入れたらまた鳴らし始める。切ってすぐ入れ直したときは、止める予約を取り消すだけで鳴りは途切れない
- 空きがなくて鳴っている声部を横取りするときは、音量を 5ms で 0 まで下げてから高さ・音色を変えて鳴らし直し、音量も 5ms で戻す（STEAL_SEC）。鳴っている途中で周波数を瞬時に変えると段差（プツッ）になるため。横取りした音だけ 5ms 遅れる（光とのずれは感じない大きさ）。キックとサブはそろえて遅らせる

## D60 花の種類を選べるようにする（ひまわり・彼岸花・デイジー・花畑）
- 光の小窓の flowers の下に kind を足した: mixed（今までの 12 種から1輪ずつ選ぶ）/ sunflower / spider lily（彼岸花。キーは `spiderlily`）/ daisy / meadow。小窓は英語なので、最初の higanbana から英名に改めた。この端末の設定として保存する（`flowerKind`）
- 種類ごとに形・色・咲き方・葉・散り方をまとめて決める（`SPECIES`、`src/render/flowers.ts`）。種類の色は図形の色（音程）から作らず、white モードでもそのまま色を付ける（青いひまわりや白い彼岸花にならないように。D57 の「うっすら色づく」より一歩進めた例外）
- ひまわり: 黄色い舌状花が2列、大きな茶色の円盤。円盤の種は黄金角のらせん（n 粒目は半径 √(n/N)・角度 n×137.5°）をフラグメントシェーダで描く。花びらは円盤の縁から出す（中心から出すと円盤が花びらに埋もれた）。正面寄りに咲き、落ちるときは首ごと落ちる。葉は緑で大きめ、花はまばら
- 彼岸花: 細い6枚が鉤のように反り返り、縁が縮れる。長いしべ（6本 + めしべ）が外へ弧を描き、先の葯が光る。4〜6 輪が1つの丸い頭に集まって四方を向き、蔦から伸びるまっすぐな長い茎（少し弓なり）の先に咲く。咲く時期に葉がない花なので、葉は出さない
  - 最初は茎がなく大きく、房を扇形に広げたので、画面が赤い塊だらけになった（カオス）。茎を線で描き（花の部品 kind 5）、小さく（0.55 倍）・まばらに（間隔 2.2 倍）した。形を直したあと、少なく感じたので間隔を 1.3 倍に戻した。形は参考のイラスト（丸い頭・鉤の花びら・弧のしべ・長い茎）に寄せた
  - 反りは最初 2〜2.6 rad で花びらが輪になってしまったので 1.1〜1.4 rad に
  - 実物を調べて形を直した（図鑑の記述と写真）: 5〜7 輪が花茎の先に散形に付き、それぞれ横を向く。花被片は6枚、狭い倒披針形（長さ約 40mm・幅 5〜6mm）で縁が波打ち、強く反り返る。雄しべ6本は花被片の約2倍（約 8cm）で、花の向きに沿って前へ突き出し、先が上へ曲がる。写真で見ると、しべは房全体で左右に大きく広がる扇になる
    - それまでは、しべを花の軸のまわりに円錐状に広げていたので、四方へ散って形がおかしかった。しべは花の軸に沿った細い束（軸から 0.38 rad）にし、先を画面の上へ反らせた。花被片は細く（半幅 0.07〜0.085）して、2〜2.5 rad 反らせる
    - しべは、先だけ上へ曲げるとまっすぐな棒に見えて長すぎた。花から出る向き（3D を画面に写したもの）から、付け根から先まで同じ割合で画面の上へ曲がる弧（合わせて 1.3 rad）として描くようにし、長さは花被片の 1.5 倍に縮めた。葯は先の小さな点に
    - 反りの強い花びら・しべは、中心線を曲率一定の弧として積分して描くようにした（付け根からの向きだけで近似すると、強く反らせたときに巻かずに潰れた）。mixed の花は今までの近似のまま
  - 上へ伸びる花にした（`upright`）: しべは上へ向かって生え、花びらは上下へ出て巻く。房の花は縦の軸のまわりに輪になって横（少し上）を向き、しべは画面の上へ反る（下を向いたしべも先が跳ね上がる）。茎は蔦の外側から空の方へ寄せるので、縦の辺や下向きの辺からでも頭は上を向く
- デイジー: 白く細い花びらに黄色い花芯（小さな種のらせん）。添え花ありで野原のように
  - 最初は花びらを淡い桃色の白（輝度 0.6）にしたら灰色に濁った。花の陰影で全体が暗めになるので、色のある花は色に見えても、白は灰色になる。彩度をほぼ 0 にして輝度を 1.6 に上げ、花芯の黄も少し明るく（0.65）した
- 花畑（meadow）: 野の花畑の写真（小さな花がびっしり咲き、いろいろな花が混ざり、同じ色がまとまって帯になる）を目指した
  - 形と色の組（`variants`）: 紫の小菊（22%）・すみれ（13%）・赤い八重（10%）・オレンジのポピー（9%）・キンポウゲ（黄、8%）・桃の小菊（7%）・わすれな草（空色、7%）・赤紫の小菊（7%）・薄紫の小菊（6%）・珊瑚色のポピー（5%）に、白のカモミール（16%）・青の矢車菊（8%）・青の桔梗（7%）を足した（割合は重みで、合計で割って使う）。最初は6種だったが、色を増やした。白いカラー（1枚の苞を巻いて漏斗に）も入れていたが、横から見ると紙飛行機のようだったのでやめ、そのぶん白のカモミールを増やした
  - 組は1輪ごとの乱数ではなく、画面の場所のノイズ（260px の帯 + 90px のまだら）で選ぶ。近くには同じ組が咲いて色の帯になり、境目は少し混ざる。図形をまたいでも帯がつながる
  - 小さめ（0.55 倍）に、間隔を詰め（0.4 倍）、房ごとに添え花を 2〜12 輪、蔦の両側へ 100px まで広げて咲かせる。蔦は 1.4 倍まで伸びる
  - 豪快に（`burst`）: 当たった所から、長さのばらばらな茎が放射状に 16 本伸び（花の大きさの 4.5 倍まで、上寄り）、近いものから順に一気に咲く。花火のように
  - ばらばらに伸びる（`faceJitter`・`rise`）: 花は蔦から生え、長さのばらばらな茎で外へ伸びる（茎は最初は細い緑の線で描いたが、花畑には要らなかったので描かない）。向きは蔦の外側から ±1 rad ずらし、少し上へ寄せる。蔦から離れた所にそのまま置くより、伸びて広がった感じとボリュームが出る
  - すだれ（`cascade`）: 花の場所の 45% で、花の房が弓なりに垂れる（外・少し上へ出てから下へ。花の大きさの約 4.5 倍垂れる）。房の花は 5〜9 輪で、先ほど小さく、上から順に 0.6 秒かけて咲き進む。茎は先の1輪から1本だけ描き、茎の弓なり（`stemBend`）と同じ式で花を並べるので、花が茎に沿う
  - 茎を線で描く種類と花畑は、付け根の2枚の葉（茎の代わり）を出さない。花畑では葉が重なって緑が光りすぎた
  - 混み具合の判定を、周に沿った距離だけでなく蔦から離れる向きのずれも見るようにした（添え花が同じ所で弾かれないように）。小さな花の種類は判定の距離も縮める
- 朝顔も作ったが、花畑に置き換えてやめた（漏斗形・散らずにねじれてしぼむ動き・1輪ごとの色。悪くはなかった）
- 重さ: GPU は使ったことのある枠（花びら・花芯・葉のインスタンス）を毎フレーム全部処理する（消えた花も頂点シェーダで画面の外へ飛ばすだけ）
  - 花畑は 1 秒に約 7000 枚を咲かせ、1枚が咲いてから消えるまで約 13 秒なので、約 9 万枚が同時に要った。小菊（紫・桃・赤紫・薄紫）の花びらを 16〜24 枚から 10〜14 枚にし（幅を広げて補う。小さいので見た目は変わらない）、赤い八重を 6+6 枚から 5+5 枚にして、約 4800 枚/秒（3割減）にした
  - 上限は 49152 → 65536。足りないときは古い順に上書きするが、一番古いのは落ちて暗くなった花なので、少し早く消えるだけで済む。Mac の Chrome では 60fps
- 点検で直したもの
  - 花ごとの乱数の種を step * 64 + k にしていたが、花畑は1回で数百輪咲かせる（k が 64 を超える）ので、次の step の花と種がぶつかって同じ花が咲いた。step と k から hash で作るようにした
  - 蔦の乱数（花ごとに 8 個の枠）を超えて使ったり、用途ごとの範囲が重なったりして、すだれの有無と隣の花の傾きなどが連動していた。花火・すだれ・添え花・向きのずれは、それぞれ別の乱数の系列にした
  - 同じ所に続けて当たると、花火とすだれが咲いている上に何度も重なった。普通の花と同じ混み具合の判定を、花火・すだれ専用の列で見るようにした
  - 花畑の添え花の振る舞いを「上限が 2 より多い」で切り替えていたのを、`fill` として明示した
- あわせて直したもの: 花芯の円盤は板の 3 分割から作っていたため三角形だった。板を広げて丸く切り抜くようにした（mixed の花芯も丸くなる）

## D61 全体の音量を上げる・始める前に音量の注意を出す
- Mac のイヤホンで小さかった。出力を測るとピーク約 -24dBFS・RMS 約 -35dB で、リミッター（-1dB）まで 20dB 以上余っていた（iPhone はスピーカー側が大きいので気づかなかった）
- コンプの後に +12dB（`MAKEUP_DB`）を足した。ピーク約 -11dBFS・RMS 約 -23dB。重なったときはコンプとリミッターで抑える。声部どうしの釣り合いは変えない
- 押すとすぐ玉が落ちて鳴るので、「click to start」の下に小さく音量の注意を出す
- どの口も step 0 で一斉に玉を出すため、押した瞬間に重なって「ボフ」と鳴っていた。始めたときだけ各口の最初の1回（step 0）を出さない。格子はそのままなので、2 : 3 なら 2 拍後・3 拍後にばらばらに落ち始める。その後 6 拍ごとに頭がそろうのはポリリズムなのでそのまま
  - 先に t0 を 1.2 秒後ろへずらしたが、その間は図形も描かれず、図形が出た途端に玉が落ちるだけだったのでやめた
- 始めの「ボフ」には図形の確定音も混じっていた。始めの配置（保存した配置・デモ）も step 0 に図形を置くので、確定音が鳴っていた（同時刻は1回にまとめるが、1つ目の図形の楽器で1発鳴る。circle ならキック）。確定音は人が置いたことを耳で知らせるものなので、読み込み（`loadScene`・デモの `loaded: true`）で置いた図形には鳴らさない（`ShapeAddedEvent.loaded`）。シーンを切り替えたときも鳴らない

## D62 当たった点の表示を増やす（crosshair・notes・scope・stars）
- readout（D36）と同じく、どの背景とも組み合わせられる計器・グラフィックの表示を4つ足した。光の小窓の on hit にそれぞれのオン・オフ（既定はオフ）。この端末の設定として保存する（`crosshair`・`noteNames`・`scope`・`constellation`）
- 候補には画面全体を揺らすもの（衝撃波のゆがみ・RGB ずれのグリッチ）と物理のもの（火花）もあったが、readout に近い計器系を先に作った
- **crosshair**（`src/render/crosshair.ts`）: 当たった点から縦横の細い線が画面の端まで伸び（0.22 秒）、1.4 秒で消える。当たった点のまわりは少しあけ、目盛り（16px ごと、3つごとに長く）を付ける。0.12 秒に1つまで、同時に最大5つ
- **notes**（`src/render/notes.ts`）: 当たった点に音名（E♭4 など。黒鍵は ♭ で書く: 曲に A♭・E♭・B♭ があるので）と MIDI の値・velocity が出て、上へ昇りながら 1.6 秒で消える。chord で重ねた音は同じ表示に並べる。echo / rise のくり返しは小さく、先頭に回数の点を付ける。表示名は notes、キーは `noteNames`
- **scope**（`src/render/scope.ts`）: 当たった点を中心に、出力の波形がオシロのように横へ伸びる。リミッターのあとに AnalyserNode（2048 点）をつなぎ、出てから 0.28 秒は毎フレーム取り直し（音の立ち上がりを見せる）、あとは止めて消える。上向きに 0 を横切るところから 20ms 分を描き、ピークで正規化する。両端は細く絞る。音を出していない（ミュート・MIDI だけ・始める前）ときは、鳴らした音高の減衰する正弦波を描く。0.15 秒に1つまで、同時に最大3つ
- **stars**（`src/render/constellation.ts`、キーは `constellation`）: 当たった点を星（小さな十字）として残し、0.9 秒以内に続けて当たった点どうしを線で結ぶ。14px 以内にまた当たったら星を増やさず明るくする。区間（8小節）が変わると、それまでの星座は 2.2 秒で消えて描き直す
- 照準線・波形・星座は echo / rise のくり返しには出さない（同じ点に重なるだけなので）。時刻はどれも renderStep から取るので、止めると止まる

## D63 光の小窓の on hit を並べたボタンにまとめる
- D62 で on hit が7つのスイッチの行と7行の説明になり、縦長の画面では backdrop までスクロールが要った
- スイッチの行をやめ、drip / flowers / readout / crosshair / notes / scope / stars を文字だけのボタンで横に並べた（`Section.chips`）。いくつでもオンにでき、オンのものは選択肢と同じく白く、下に点
- 説明は下の1行にまとめる。マウスを載せたもの・最後に押したものの説明を出し、何も触っていなければ「turn on what shows up where a ball hits」
- 付くつまみ（drip speed・花の種類）は、オフのとき薄くするのをやめて、オンのときだけ出す（`Section.showIf`）。ボタンの下に離れて並ぶので、表示名を drip speed / flowers にした
- motion・sound・settings の説明の出し方は、まずこの小窓で見てから決める

## D64 小窓の説明を区切りごとに1行にまとめる
- D63 の on hit と同じく、motion・light・sound・settings の説明を、行ごとではなく区切りの一番下の1行にまとめた（`Section.hint` は直前の行に説明を結びつけるだけになった）
- マウスを載せた行の説明を出し、離れたら最後に触った（押した・動かした）行の説明に戻す。タッチでは押した行の説明になる。何も触っていなければ最初の行の説明。説明の出ている行は見出しを明るくする（説明が1つだけの区切りでは明るくしない）
- 付くつまみはオフのとき薄くするのをやめ、オンのときだけ出すようにそろえた（`showIf`）: tail の長さ（trail style が tail のとき）・hum vol（hum がオンのとき）・backdrop の level（none 以外のとき）。薄くする仕組み（`SliderOpts.enabled`）は使うところがなくなったので消した
- light の trail の長さのつまみは、表示名を trail から tail に（選択肢の tail / blur と合わせる）。trail style の説明は選んでいる方（tail / blur）を言い、長さの説明はつまみに付けた
- sound の hum の説明が hum vol の行に付いていたので、hum の行に付け直した
- on hit のボタン（D63）は小窓の左端から並べていたが、下の選択肢（花の種類・backdrop の kind）と左端がそろわなかった。ほかと同じく見出し（show）の付いた行にして、ボタンの列を選択肢の列にそろえた

## D65 後処理の全画面の書き込みを 4 回から 2 回にする
- 測ってわかったこと（開発時のブラウザ（Chromium）、キャンバス 1884×1986、表示を全部オン）
  - CPU は 1 フレーム約 1.2ms（蔦 0.45・後処理の発行 0.4・sim 0.1、D62 の表示は合わせて 0.1 未満）。重いのは GPU
  - GPU（timer query）: 描画 6.7ms・残像 6.5ms・UnrealBloomPass 8.9ms・OutputPass 8.1ms。重さはほぼ画素数で決まり、全画面を書くパスが 4 つ（残像の蓄積・見せる絵・グローの足し戻し・書き出し）あった
  - 49fps で、自動の画質（D27）が MSAA を切っていた
- 残像（FlowPass）がグローと書き出しも受け持つ。見せる絵（今の絵と残像の明るいほう）を全画面に書かず、グローの明るいところの抜き出し（半分の解像度）と最後の書き出しが、それぞれ 2 枚から直接組み立てる。UnrealBloomPass はぼかしだけ使い、抜き出しの素材を差し替え、最後の足し戻しは 1×1 のダミーに向ける。書き出しはグローを足してトーンマップ・色空間（three が画面に描くときに足す関数）
- 後処理の GPU 時間 23.5ms → 10.9ms、MSAA を付けたまま 57fps
- 見た目は同じ: 止めた絵で旧と新を比べて、drip オフは画素の差が最大 1/255。drip オンは、グローの抜き出しが「2 枚を補間してから明るいほう」になる分だけ違う（平均 0.24/255、8 を超える画素は 0.004%）

## D66 シーン描画を軽くする（背景の升目の場・MSAA のバッファ）
- D65 のあと、シーン描画（RenderPass）が 1 フレーム 8.1ms（DPR 2、1884×1986、背景 ascii）。内訳は、何も描かないときの土台 1.7ms、MSAA 4 の分 3.4ms、背景 ascii の分 3.2ms（MSAA なしで測った差）
- 背景の bitmap・ascii は、升目の中は同じ値（ノイズ 2 つと当たり 16 個の和）なのに、全画面の画素ごとに計算し直していた。DPR 2 だと升目 1 つに 240〜500 画素ある
  - 升目の数の大きさ（ascii で 105×71）の float の texture に、升目ごとの値を 1 回だけ描き、描く側は texelFetch で読む（layer.ts の CellField）
  - 計算は同じなので、絵は旧と新で画素まで同じ（止めた同じ時刻の絵で差 0）
  - 背景の分: ascii 約 2.7ms → 0.8ms、bitmap 約 2.2ms → 0.8ms 前後
- MSAA は外さない。2 倍に減らすと 1.4ms 軽くなるが、4 倍と比べて縁の画素が 5 万ほど平均 18/255 変わり、線の縁の見え方が変わる
  - 代わりに今の絵のバッファを半精度の RGBA（1 画素 8 バイト）から R11G11B10F（4 バイト、アルファなし）にして、MSAA のクリアとまとめ（resolve）の読み書きを半分にする
  - 今の絵のアルファは使っていない（クリアが 1 で、足し合わせで下がらない）。値の差は平均 0.8/255、最大 10/255（4 を超える画素は 123）で、トーンマップ後には見えない
  - シーン描画だけで測って 1.2〜1.6ms、フレーム全体では 0.3〜1.1ms 軽くなる（中身が動くので幅がある）。R11G11B10F に MSAA 4 で描けない端末では、これまでどおり半精度の RGBA
- 残像・グローの描き込み先は半精度のまま。R11G11B10F は青の精度が 5 bit しかなく、少しずつ暗くする残像では暗くなりきらずに色が残るおそれがある

## D67 自動の画質（D27）を上げ直す
- 図形を 20 個まとめて足した直後の数秒の重さで q3（解像度 0.6）まで下がり、落ち着いて q0 でも 60fps 出る状態になっても下がったままだった（D27 は上げない作り）
- 2 秒ごとの平均が 57fps より速い状態が 10 秒続いたら、1 段上げてみる。60Hz の画面で張り付いていれば満たし、52fps などぎりぎりのときは上げない
- 上げてから 4 秒のうちに遅く（48fps 未満）なったら、下げ直して、次に試すまでの待ちを倍にする（10 → 20 → … → 160 秒）。4 秒を越えて保てたら待ちを 10 秒に戻す
  - 本当に重い端末でも、行き来は最初の数回と、その後は 160 秒に 1 回の数秒だけになる
- 開発時のブラウザで確かめた: 毎フレーム 30ms 止める重さを 6.5 秒かけると 2 秒ごとに q3 まで下がり、止めたあと 18・28・38 秒で q2・q1・q0 に戻った

## D68 画質を設定で選べるようにする
- 自動の画質（D27・D67）は、重いと知らせずに画質を下げる。勝手に変わるのを避けたい場面（見せる・録る）のために、設定の Setup の resolution の下に quality を置いた
  - auto（既定）: これまでどおり、重いと下げ、軽くなったら上げ直す
  - high = MSAA 4、mid = MSAA なし、low = MSAA なしで後処理の解像度 0.75。重くなってもそのまま動かさない
- 端末ごとの設定として保存する（prefs）。auto に戻すと最高から測り直す。`?fps` の q0〜q3 は選んだ段階を出す

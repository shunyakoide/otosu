# ステップ2 物理・インタラクション: レビューと改善案

## 1. 実装レビュー（decisions.md との照合）

おおむね D1〜D8 どおり（120Hz、`periodSteps` の整数固定、発音の判定を sim だけで行うこと、遅延からの復帰、V_MIN/REST_VN/クールダウン、ω_max）。
以下はずれとバグ。上ほど重要。

**B1. 回転を OFF にすると、物理の線が1ステップ前の角度のまま止まる**（`src/sim/sim.ts:113-116, 149-158, 178-180`）
- 再現: rotate ON → 長い線を回す → OFF。`setSegmentRotation` は `theta0 = 角度(s)` に焼き込むが、`updatePoses` は `omega===0` の線を飛ばすため、`ax..by` は角度(s−1)のまま残る
- 描画は `theta0` で描くので、見えている線と当たる線が端で最大 `ω·halfLen/120`（上限 0.9R ≈ 5.9px）ずれたままになる
- 修正: `setSegmentRotation` の最後で姿勢を必ず計算し直す（または線に dirty フラグを持たせる）

**B2. 回転の変更が描画に先に出てしまう（D8-5 違反）**（`src/render/render.ts:277`, `src/sim/sim.ts:149`）
- render は sim と同じ Segment オブジェクトを参照している。rs は sim より LOOKAHEAD＋出力遅延ぶん過去なので、rs < s の時点を新しい `theta0/omega` で計算してしまう
- 症状: ON/OFF や速度変更の瞬間に、線が数ステップぶん跳ぶ・一瞬逆に回る
- 修正: `segmentPose {step, id, theta0, rotStartStep, omega}` イベントを出す。render は自分用のコピーを持ち、`rs ≥ step` になってから反映する

**B3. 右クリックの消去判定が、先行している sim の姿勢で行われる**（`src/input/input.ts:57-58`）
- 回転中は、見えている線と `sim.segments` の姿勢が「端点の速さ ×（0.05s＋出力遅延）」だけずれる
- 例: 1rad/s・半長 500px なら約 40px ずれ、`ERASE_RADIUS=12` では端のほうを消せない。まだ表示されていない線も消去の対象になる
- 修正: Input に renderStep を渡し、`segmentAngle(seg, rs)` と render 側の線集合（表示中の線）で判定する

**B4. 放出口の表示に sim の現在値を使っている**（`src/render/render.ts:348`）: pattern を変えると、rs より先に放出口が動く。`emit` イベントに x,y を載せ、描画は最後の emit の位置を使う

**B5. 回転中、離れていく面での空振り**（`src/sim/sim.ts:260`）: 相対速度で見て `vn≥0` のとき `bounce` が何もせず return する。次の反復でも t≈0 で同じ面に当たるので、4回ぶん反復を使い切り、そのステップの移動が失われる（小さな引っかかり）。そのステップ内ではその線を候補から外せばよい

**B6.（将来の地雷）回転の向きが `seg.id % 2` で決まる**（`src/sim/sim.ts:156`）: Undo や読み込みで id が振り直されると、同じ配置なのに逆に回る。向きは線の属性として持たせる

**テストの不足**（`test/sim.test.ts`）: 回転のトグル（B1）、V_MIN と各クールダウンの境界、setTempo 後に周期へ戻るか、を検証するテストがない。

## 2. 「放置しても展開し続ける」ための改善案（優先度順）

### P1. 放出口のゆっくりした移動（決定論的な揺らぎ）
- **狙い**: 配置は同じでも、落下点が少しずつずれて当たる線や跳ね方が変わり、数分単位で曲が移り変わる。周期構造（ポリリズム）は保つ
- **仕様**:
  - 放出位置は放出番号 k の関数にする: `x = baseX + A·f(k)`。ステップの関数にはしない（1個のボールが持つ位置は1つだけ）
  - `f` は2つのモードから選ぶ
    - drift: 周期 P 回の三角波（例 P=64 回）
    - phrase: N 回ごとに4つの候補位置を巡回する
  - A は GUI で 0〜80px（既定 24px）。x は整数 px に丸める
  - 周期全体は `LCM(P×period)` になり、長いけれど必ず巡回する
- **変更**:
  - `sim/types.ts`: Emitter に `baseX, driftAmp, driftMode` を追加。`emit` イベントに x,y を追加（B4 も同時に解消）
  - `sim/sim.ts`: `emit()` で位置を計算する。Command に `setDrift` を追加
  - `main.ts`: GUI を追加
  - `render.ts`: 放出口は emit の位置を補間して描く
  - テスト: 周期全体での一致を検証する
- **決定論性**: 状態を持たない純関数なので保たれる。sin の代わりに三角波と整数の丸めを使えば、JS エンジンによる差も出ない

### P2. 配置の保存と読み込み（URL ハッシュ＋localStorage の自動保存）
- **狙い**: 投影の現場でリロードやクラッシュが起きても同じ曲に戻れる。配置を「作品」として共有できる
- **仕様**:
  - Scene は `{v:1, bpm, pattern, rotate, rotationSpeed, drift, segs:[[ax,ay,bx,by,dir]...]}`
  - 座標は **入力の時点で** 整数 px に丸める（こうすれば、ライブ中と読み込み後の状態が同じになる）
  - `#s=` に base64url で書く。変更のたびに（debounce して）localStorage にも保存し、起動時はハッシュ → localStorage の順で探す
  - 読み込みは1つの `loadScene` コマンドで行う: 線とボールを全部消す → id 採番をリセット → 放出口の anchor を s にする → 線を追加
- **変更**:
  - 新規 `src/scene/scene.ts`（純関数の encode/decode とバリデーション）
  - `sim/types.ts`, `sim/sim.ts`（`loadScene`、線に `dir`）
  - `input.ts`（座標の丸め）、`main.ts`（GUI の save/copy URL、キー S）
  - テスト: 往復変換で一致すること、読み込み直後からのヒット列が元の再生と同じになること
- **決定論性**: 同じブラウザでは完全に再現する。ただし `Math.hypot/pow/atan2/cos` はエンジンによって末尾の桁が違いうるので、別のブラウザでは軌道がずれることがある。「同じ配置 → 同じ曲」を保証するのは同一エンジン内と明記する（完全に揃えるには数学関数を自前実装する必要があり、ステップ3以降に回す）

### P3. 線の端点ドラッグ編集＋Undo
- **狙い**: 消して引き直さずに音程（長さ）や角度を微調整でき、ライブで少しずつ曲を変えていける。失敗しても怖くない
- **仕様**:
  - 表示中の姿勢（rs、B3 と同じ方法）で端点から 14px 以内を押すと、端点のドラッグになる。中点を押すと平行移動
  - 確定するのは離したときだけで、`moveSegment {id, ax..by}` を出す。ドラッグ中はプレビューだけで、元の線は鳴り続ける（連続で更新すると音が乱れるため）
  - 長さが変わると音程を決め直し、`segmentAdded` と同じ扱いで発光させる
  - Undo（Cmd/Ctrl+Z、50段）: Input が逆操作を積む（add↔remove、move↔move、clear→まとめて復元）。復元は同じ id と `dir` で行う（B6 の対策）
- **変更**: `input.ts`（ヒット判定・ドラッグ・履歴）、`sim/types.ts`・`sim/sim.ts`（`moveSegment`、`addSegment` に id と dir を任意で渡せるようにする）、`render.ts`（ドラッグ中の表示）
- **決定論性**: コマンドはステップの境目で適用するので、影響はない。（ステップ, コマンド）の記録を残せば操作ごと再生でき、将来の録画・再演に使える
